# 前言：从好奇开始，把所学用起来

我们和 AI 打交道的方式正在悄然改变。过去，我们大多只是向聊天框讨要一段文字或一个解释；如今，我们把几份零散通知、一学期的课件，乃至整座代码仓库交给它，期待它自己查资料、调工具、改文件，最后交回一份靠谱的结果。可真正用起来就会发现，它有时聪明得惊人，有时却在最基础的地方翻车：开头千叮万嘱的约束聊到第 30 轮就忘得一干二净，原始材料里压根没写的事张口就来，或者卡在同一个报错里反复兜圈子，连改十遍测试也没修对真正的问题。

遇到这些时刻，把原因归结为“模型还不够聪明”或“提示词没写对”，往往使不上劲。只要掀开外壳看一眼就会明白：真正把事做成的从来不只是一个会说话的模型，而是一整套相互咬合的 Agent 系统。**模型**只负责根据当前喂给它的输入提出下一步建议；真正去读文件、查资料、跑命令的是**工具**；决定把哪些信息装进本轮窗口、拦下高危操作、在超时后核对真实状态的，则是统筹全局的**宿主程序**。

看懂这套**循环、上下文与边界**的协作机制，绝不只是系统工程师的专利。准备讨论课的老师明白了“文件存着不等于这一轮读到了”，就知道怎样引导学生追查一手出处；日常整理简报的职场人看懂了“工具权限与完成证据”，就不会听 AI 说一句“已处理完毕”便匆忙对外转发；而正在编写自动化工具的开发者，则能跳出零散的调优经验，直面上下文裁剪、沙箱隔离与异常恢复背后的工程取舍。

这正是写《图解 Agent 系统》的初衷。我们不想堆砌转瞬即逝的行业黑话，也不想把源码导读写成流水账式的函数点名，而是用一张张职责分明的图解与看得见字节变化的数据流，把抽象概念放回真实的任务现场。你可以不写一行代码，顺着“整理几份材料、核对每处来源”的日常主线看透核心机制；也可以顺藤摸瓜，走进 Pi、Codex、OpenCode、LangGraph 等开源项目的关键代码，看一线团队如何把那个核心循环写得既简洁又抗造。

书中的每张架构图都配有文字说明与可编辑源文件，开源项目篇也如实标明了核对过的固定 commit 与静态阅读边界，方便你随时回到一手材料查证。你可以从头顺读，也可以带着手头正头疼的问题跳读；翻到一张有共鸣的图时，不妨停下来，试着用它复盘一次你最近遇到的 AI 失误——当你能指着图上的某条箭头说出“原来卡在这里”时，这套系统就已经真正为你所用了。
