# 阅读指南：从问题进入

这不是要求从第一页读到最后一页的项目百科。正文以机制为主线，项目是有边界的案例；同一个问题可能在几个系统中得到不同答案。你可以选择一条路线开始，再沿章节中的链接交叉阅读。

## 四条阅读路线

**先理解机制。** 从[一次 Agent loop](../../docs/concepts/agent-loop.md)里的读书会任务，看懂目标怎样变成有出处的回答；再用[一项任务中的五层职责](../../docs/concepts/model-harness-cli-mcp-skill.md)区分模型、运行器和工具，然后按需读[Agent、工作流与多 Agent](../../docs/concepts/agent-workflow-multiagent.md)、上下文、记忆、审批和扩展。每章先抓住“谁决定、谁保存、谁执行、谁验证”，再看项目映射。

第一次遇到这些词，可以先这样区分：**模型**依据当前输入提出下一步；**工具**完成读文件、搜索等具体操作；**运行器／宿主**是包住模型与工具的程序，组织下一轮，并决定是否允许工具执行。上下文是模型这一轮收到的信息，不等于系统保存的全部历史。更完整的术语解释见[术语表](../../docs/glossary.md)。

**沿项目追源码。** 从 [Pi 的分层](../../docs/systems/pi/README.md) 进入一条实际运行路径，然后打开章内的代码导读。读系统篇时，先确认上游仓库、固定 commit 和研究范围，再沿“入口 → 状态 → 分支 → 副作用 → 结束或恢复”追踪；不要把一条局部路径误读成项目全貌。

**带着设计问题查阅。** 如果你正在决定如何保存会话、拦截动作或判断完成，先读相应机制，再看[横向对照](../../docs/comparisons/README.md)。比较只针对同一个问题和已有证据，不给项目排总名次。

**可选：做一个小实验。** 想亲自观察时，按[从零学习路线](../../docs/learning-path.md)选择[本地配置练习](../../docs/labs/first-agent-loop.md)，分清提案、许可、文件写入和任务检查；再选[上下文预算练习](../../docs/labs/context-budget.md)，比较保存记录与本轮输入；需要理解外部副作用时，进入[回执丢失练习](../../docs/labs/remote-effect.md)，看没有回执为什么不能断定结果。它们只用 Python 标准库和确定性脚本，不需要模型账号。不会 Python 也可以先预测表格中的结果，再对照轨迹；这些实验都不是看懂图解的前置条件。

已经在用 Codex 或 Claude Code 的读者，也可以用[五层职责](../../docs/concepts/model-harness-cli-mcp-skill.md)分析自己的任务：项目约定从哪来、Skill 何时读、MCP 提供什么、动作在哪里受限。自己的工具轨迹与书中的教学模拟是两类证据，不能互相代替。

## 和 AI 一起读

看图、解释、换个例子，是这条可选路线的三个动作。

你可以把常用的 AI 助手当作学习搭档：卡住时请它拆开一句话，看懂后请它追问，再换一个任务试着解释。**本书提供可以回看的图、例子与来源，AI 提供按你的问题展开的对话。** 两者不是必需绑定的产品；不用 AI，也能沿正文完成阅读。

不用把整本书一次交给 AI。先选一章，把相关段落和自己的疑问粘贴过去；看图时可附清晰 PNG。如果助手读不了图，改用该图的文字版，不能让它猜箭头或小字。网址不等于助手已经读到页面，开始前确认它实际收到哪些材料。

### 按需要选一种用法

| 你现在的需要 | 请 AI 帮什么忙 | 留给自己做什么 |
| --- | --- | --- |
| 看图还不太懂 | 用熟悉的例子解释一个节点或一条箭头，区分原文与补充类比 | 回图指出这段解释对应的位置，不把类比当实际实现 |
| 想知道自己懂没懂 | 听你的复述，每次追问一个关键关系；答错先给提示 | 自己说清正常过程，再预测一项条件变化的结果 |
| 想继续读源码 | 拆解章内固定版本的一小段代码，整理调用顺序和待核问题 | 打开原文件核对；没实际读取源码的解释不当作源码结论 |

熟悉的地方直接读，不必逐章对话。遇到陌生词或一个真正卡住的问题，再邀请 AI 加入；它不需要替你生成一份新的“全书总结”。

### 一段可直接使用的开场

下面只是对话约定，不是能保证模型遵守的系统门禁。先粘贴所读材料，再补一句自己的理解或疑问：

```text
我在读《图解 Agent 系统》，请陪我理解下面这一小段材料。
先确认你实际收到的材料，不要假定已打开网址或看清图片。
围绕材料中的一个关系，每次问我一个问题，等我回答再继续。
我说卡住时，先给一个简短例子或提示；我要求完整解释时再展开。
反馈指出我的哪句话需要改，并给出材料中的对应位置。
随后换一个小例子，让我先预测，再一起检查；不要先公布答案。
补充知识或类比请与原文分开；材料不能确定的地方说不确定。
```

### 试一次：记忆怎样进入回答

先读[上下文与记忆](../../docs/concepts/context-vs-memory.md)及其[图的文字版](../../figures/context-vs-memory/README.md)。设想一份报名说明写着“周五截止”：助手保存这条信息，提问时检索到它，并把它装进本轮输入。先指着图讲清这条正常路径，再请 AI 听你的解释。

例如，你可以说：“说明先存起来，提问时被选中，再放进模型这轮收到的资料。”请 AI 检查这三步是否与所给材料一致，而不是只问它“我懂了吗”。接着自己提出变化：“如果仍然保存着，但这一轮没有选进输入，能只凭这次输入确定截止日期吗？还缺什么？”**先写自己的判断，再让 AI 追问理由；判断仍须回到书里的材料核对。**

读完后暂时放下 AI 和原文，换成一个新的例子：完整日程仍在磁盘，工具这次只返回了集合地址，没有返回时间。用户问“几点集合”，你能仅凭这份结果回答吗？先说哪些资料实际可见，再解释下一步需要读取什么。能在新例子里区分可访问的材料和实际输入，比获得一句“回答正确”更有用。这里是一种学习方式的示例，不是模型实测或学习效果实验。

想继续试，可读[Agent loop](../../docs/concepts/agent-loop.md)预测何时停止调用工具；或读[职责分工](../../docs/concepts/model-harness-cli-mcp-skill.md)，先自行安排只读搜索工具的角色，再与 AI 对照。不必安装框架。

### 留下一张自己的理解卡片

在纸上或自己的 Markdown 笔记里留四行即可：所读章节（附链接或阅读包版本）、用自己的话解释的一个关系、换个例子的判断、仍待核对的问题。下次先自己复述，再翻书或请 AI 帮忙；不用照抄整段聊天，也不依赖助手永远记得进度。不同版本的图和源码不要混成同一次阅读依据。

AI 的解释和引用也可能有错。请它指回具体段落，打开对应来源核对，不把流畅表达、肯定语气或自评分当成理解验收。仅使用公开书稿或自己愿意分享的例子，不上传密钥、私人笔记或未获准传播的课程材料；若选择运行代码，先看清将执行的命令及读写范围。

这套轻量方法参考 [OpenAI 的材料驱动学习建议](https://learn.chatgpt.com/use-cases/build-exam-study-system)中按来源组织问题、结合解释与应用、根据卡点复习的思路；不是对本书学习效果的证明。不同助手的图片、文件与联网能力需按其实际功能核对，书内方法不绑定某个品牌或付费套餐。

## 怎样读图与证据

概念图是帮助思考的抽象，不声称某个项目恰好按图实现；项目实现图则须能回到固定版本的源码或官方文档。每张正式图都附有文字说明和可编辑图源。箭头表示什么，应由图注与正文解释，不能只靠颜色猜。

书中区分**源码事实**、**文档声明**、**运行观察**、**工程推断**和**未知**。例如，读到一个函数的分支，是源码事实；官方文档描述的行为是文档声明；只有记录环境、输入、版本和结果，才称得上运行观察。由证据推导的设计解释应保留“推断”身份，资料不够的地方就标为未知。[来源规则](../../sources/README.md)说明了这套标记。

图示、测试结果与模型的“完成”回复都不能单独替代任务验收。遇到关键结论，建议点击章内固定源码链接核对版本与条件；遇到图文不一致、链接失效或遗漏的边界，请按[贡献指南](../../CONTRIBUTING.md)提交可复核的修正。
