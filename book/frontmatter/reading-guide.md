# 阅读指南：选一个起点，顺着图往下读

初学 Agent 最容易陷入两种挫败感：一头扎进几万行开源仓库，没看清主干就迷失在异步事件与配置细节里；或者只读笼统的概念文章，真遇到“AI 漏读资料”“改坏配置”“超时重复提交”时，依然不知道该去查哪一层。

翻开本书任何一章之前，不妨先在脑海里划清**三个核心角色**的职责边界：

- **模型**（Model）：只看本轮喂给它的输入内容，推理并**提议**下一步动作（例如请求调用某个读取工具，或给出最终草稿）。它是一颗被隔离在玻璃房里的大脑，自己碰不到磁盘、数据库或网络。
- **工具**（Tool）：真正触碰外部世界的手脚，负责读文件、搜资料、执行命令或调用远端接口，把原始执行结果如实带回。
- **宿主**（Host / Harness）：掌控全局节奏的调度程序——决定本轮把哪些历史与资料装入上下文窗口、拦截并审批高危工具调用、把工具回执塞回下一轮消息，以及在报错或超时后决定查询、重试还是停机。

```text
用户目标 ──▶ [宿主组装上下文] ──▶ [模型提议动作] ──▶ [宿主校验权限] ──▶ [工具执行并返回证据]
                   ▲                                                           │
                   └─────────────────── 塞回结果，决定继续或结束 ◀──────────────┘
```

全书所有图解本质上都在追踪同一件事：**这一步数据在谁手里，跨过了哪道边界，出了错由谁兜底**。其余专业名词等遇到时再结合场景理解，或随时翻查[术语表](../../docs/glossary.md)。

## 先找到适合自己的起点

- **日常学习、备课与办公场景**：直接从[把所学用起来](../../docs/learning-and-practice.md)入手。跟着几份简短材料走完“核对出处、单列待查、拆开草稿与执行”的全过程，拿纸笔就能立刻上手。
- **想按部就班建立全局认知**：打开[阅读路线](../../docs/learning-path.md)，沿着“接力循环 → 接入能力 → 源码解剖 → 故障恢复”四个台阶拾级而上，每一步读完试着用自己的话复述一遍。
- **带着具体工程故障查答案**：直接挑对应的机制篇与系统篇。架构图帮你定位问题卡在哪条链路，固定版本的源码链接带你直达实现细节。

## 四条阅读路线

- **路线一：先看透核心机制**。从 [Agent loop](../../docs/concepts/agent-loop.md) 出发，顺读[一项任务中的分工](../../docs/concepts/model-harness-cli-mcp-skill.md)与[上下文与记忆](../../docs/concepts/context-vs-memory.md)。先搞明白外部资料怎样进入本轮输入、工具动作怎样受控执行、返回结果怎样闭环验证，再按需拓展多智能体协作与异常恢复。
- **路线二：顺着真实源码解剖一个项目**。推荐从分层干净的 [Pi](../../docs/systems/pi/README.md) 起步，先读系统首页看清模块边界，再打开代码导读追踪入口函数、工具分发与停止条件。不必通读整个仓库，先顺着主干走完正常一轮，再看报错分支如何兜底。
- **路线三：围绕同一难题做横向架构比较**。当你纠结“循环何时该停”“四种状态各自存在哪”“外部动作超时后怎样防重放”，直接翻阅[横向对照](../../docs/comparisons/README.md)，把不同系统的取舍摆在同一张桌面上对比。
- **路线四：用零依赖脚本重现边界故障**。[本地循环实验](../../docs/labs/first-agent-loop.md)演示读取、审批与写入闭环；[上下文预算实验](../../docs/labs/context-budget.md)演示窗口装不下时的筛选取舍；[回执丢失实验](../../docs/labs/remote-effect.md)演示网络超时后为何必须“先查状态再决定重试”。所有实验均只用 Python 标准库，无需 API 账号即可跑通或直接阅读运行轨迹。

## 和 AI 一起读

把一整章丢给 AI 让它“总结重点”，得到的往往是正确的套话，合上页面依然画不出调用链。最高效的陪读法是**苏格拉底式对练**：把 AI 当成追问搭档，先由你讲出自己的判断，再让它顺着材料挑刺提问。

这种材料驱动的对练思路也与 [OpenAI 的材料驱动学习建议](https://learn.chatgpt.com/use-cases/build-exam-study-system) 一脉相承。开始前请注意两条安全习惯：只粘贴公开书稿或你有权分享的内容，把密钥、内部文档与私人笔记留在本地；若所用模型看图模糊，直接附上[各图的文字说明](../../figures/README.md)即可精准对齐每个节点。

### 拿来即用的苏格拉底陪读提示词

复制下面这段开场白，在后面粘贴你正在读的正文段落（或图的文字说明）以及卡住的具体问题：

```text
我在读《图解 Agent 系统》，请做我的苏格拉底式陪读搭档。
1. 先用一句话确认你收到了哪些材料与我的具体疑问。
2. 不要一次性把答案全倒给我：先给一个贴近日常或工程现场的简短提示，然后每次只追问我一个关键因果关系，等我作答后再继续。
3. 当我复述偏离原文时，请直接指出正文中对应的段落或图中箭头；若你补充了材料之外的类比，请明确标出“这是补充类比”。
4. 等我理顺后，请换一个微调了条件的新场景考我一题，让我先判断系统下一步会发生什么，再一起核对。
```

### 三种高频卡点的对练法

- **看图还不太懂。** 指着某一条让人困惑的连线，请 AI 结合正文说明这条线传的是“模型的提议”“宿主的拦截指令”还是“工具的真实回执”，再回到原图确认起点与终点。
- **想知道自己懂没懂。** 合上正文，用三句话复述核心机制，请 AI 专门寻找你漏掉的前提条件（例如“谁来判断结束”“失败后状态有没有回滚”）。
- **想继续读源码。** 把章内引用的那段关键函数贴给 AI，让它按输入参数、状态变更与返回值的顺序拆解，随后务必自己点开源码链接核对真实分支条件。

### 演练一次：为什么存了文件却答不出问题

以[上下文与记忆](../../docs/concepts/context-vs-memory.md)（配合[图的文字版](../../figures/context-vs-memory/README.md)）为例：磁盘上的文件明确写着“报名周五截止”，但只有当检索工具命中该文件、读取原文并由宿主装入本轮 `messages` 数组后，模型才真正“看见”这条约束。

你可以先向 AI 复述：“文件躺在磁盘上只是外部存储，本轮没被检索并塞进上下文窗口，模型就无从知晓。”接着做一次变体推演：假设日程文件完好无损，但这轮搜索工具只返回了活动地点，此时用户追问集合时间——系统下一步缺什么数据，宿主和工具该走哪条回路补齐？自己先给出判断，再让 AI 对照图解复核，读完随手记下四行笔记（章节、一句核心复述、变体判断、遗留问题），理解就会非常扎实。

## 怎样看图和来源

本书包含两类插图：**概念图**抽离具体框架细节，提炼跨系统通用的职责与数据边界；**项目图**严格对应某个开源仓库在指定版本下的一条真实执行路径。读图时请留意图注区分的“控制调用”“数据返回”与“状态落盘”。

所有源码导读均锚定固定 commit，并在章末清晰列出静态代码阅读边界、官方文档依据与本地实验范围。如果你在阅读中发现图文出入、链接失效或某处推导不够透彻，欢迎通过[贡献指南](../../CONTRIBUTING.md)告诉我们具体位置。
