# 把笼统的「记忆」拆回四种工程状态：结构、代价与选型

[返回四类状态对照章节](../../docs/comparisons/four-kinds-of-state.md) · [图源](scene.excalidraw) · [原尺寸 SVG（手机可放大）](diagram.svg) · [PNG](preview.png)

架构评审中最容易鸡同鸭讲的词就是“记忆（Memory）”。图中用四宫格对照矩阵把四套开源系统的代表性状态拆清，每张卡片给出存储对象、读写代价、进入模型方式与误用禁区：

1. **① 对话分支记录（Pi · JSONL 会话树）**：末尾追加事件节点，零模型调用开销；擅长单场任务内无损回退分叉试错，但不负责跨会话长期知识沉淀。
2. **② 常驻可编辑文件（Letta Code · local MemFS）**：把核心约定保存在人类可直接审阅修改的 `system/*.md` 中并编入系统提示；确定性最高，但席位有限且修改后需经系统提示重编译生效。
3. **③ 可检索原子事实库（Mem0 · 向量事实卡片）**：用写入时的模型抽取与冲突消解开销，换取跨月成千上万条碎片背景的 Top-K 按需召回；适合补充长尾事实，不适合单独承担不可遗漏的安全红线。
4. **④ 执行进度快照（LangGraph · `StateSnapshot`）**：保存工作流引擎跑到哪个节点、通道值是什么的程序现场，支撑人工审批挂起与崩溃续跑；回退快照只改图内内存，绝不会自动撤销已发往外部世界的写操作。
