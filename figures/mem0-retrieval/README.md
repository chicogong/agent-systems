# 图的文字版：Mem0 先找候选，再排序

[返回章节](../../docs/systems/mem0/README.md)

应用需要找回一条相关记忆时，把 `query`（要查询的内容）和 `filters`（限定查询范围的条件）交给 `Memory.search()`。图中的流程可以理解为“先入围，再加分，最后选出几条”。

## 一份候选名单怎样形成

1. **先按含义找相关记忆。** 语义向量检索根据内容的含义找到候选。图中的“入围记忆”就是这份候选名单。
2. **再看有没有额外分数。** 同一个问题还可以尝试关键词搜索和实体关联。BM25 是关键词匹配分数，实体关联则在匹配到有关实体时加分。这两路给已有候选提供排序分数；只有已经在语义候选名单中的记录，才能用这些分数参与后续排序。
3. **筛选、加分、排序。** `score_and_rank` 先筛掉语义分数过低的候选，再加上可用的 BM25 与实体分数，按总分排序，取前 `top_k` 条。`top_k` 是希望返回的最多条数，最后再整理结果格式。

图中“只取语义结果”说明名单从哪里来；“可用时加分”和“命中时加分”说明额外分数何时参与。这三个标注把找候选与排顺序分开了。

## 两条加分路径的条件

关键词搜索要看向量库是否支持：基类 `keyword_search` 默认返回 `None`（没有可用结果）。实体关联也可能没有命中。因此，图里的橙色支路是否带来分数，要按所选适配器和实际结果查看。

写入过程另见正文：在 `add(infer=True)` 路径中，大模型从消息提取事实，再按内容 hash 排重，调用 `insert` 保存到向量库。本图从查找开始，写入步骤留在章节中展开。

## 版本与范围
