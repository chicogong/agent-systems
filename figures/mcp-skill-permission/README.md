# Skill、MCP 与工具权限：图的文字版

看一个“查资料后修改文件”的任务：Skill 提供方法，MCP 连接材料服务，工具实际读取和修改，宿主安排调用并检查成果。图中实线连接主要步骤，虚线补充指导和拒绝时的走向。

1. **先交代要求。** 用户说明能读哪些材料、能改哪些文件，以及最后要得到什么。
2. **准备方法和工具。** Skill 提醒“先核对原文，再行动”。宿主通过 MCP 的 `tools/list` 获取工具名称、用途和参数，把需要的工具介绍给模型。
3. **选择并检查动作。** 模型建议查文档或改文件，宿主按任务范围、工具设置和产品规则检查；需要用户确认时，先取得批准。具体文档还由服务端按账户权限处理。
4. **实际执行。** 获准后，读取工具带回原文，编辑工具修改文件。MCP 的 `tools/call` 返回调用结果，宿主把它交给模型继续处理。
5. **检查成果。** 对照原要求，查看文档版本、文件差异（diff）和测试记录，说明完成了哪些部分。

读取或编辑被拒绝时，停止本次动作并说明原因，再按原任务要求等待授权、继续获准部分，或报告尚未完成。工具返回错误、材料缺失或可疑外部要求时，也要分别处理，再决定能否继续。Skill 的步骤帮助规划工作，文件有没有改、测试有没有通过，最后看实际结果。

这是教学示意，`kb.fetch` 是假设的工具名称。MCP 约定工具发现和调用的格式；工具权限与确认界面由实际产品决定。详见[正文](../../docs/concepts/mcp-skill-tool-lifecycle.md)及其[来源台账](../../sources/mcp-skill-tool-lifecycle.md)。
