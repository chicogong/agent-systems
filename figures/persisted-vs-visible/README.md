# 存下来了不等于模型本轮看见了：排查「假性失忆」的四道漏斗

[返回持久与可见对照章节](../../docs/comparisons/persisted-vs-visible.md) · [图源](scene.excalidraw) · [原尺寸 SVG（手机可放大）](diagram.svg) · [PNG](preview.png)

大模型每次推理只看得见当次 HTTP 请求体里的字节。左侧主干展示一条规则从磁盘走向生效必须闯过的四道关卡，右侧红色虚线标出每一关最常见的“假性失忆”漏点：

1. **第 1 关（物理落盘保存）**：确认工具调用真的落盘成功，排除“模型嘴上答应记住了但实际未写盘或写入报错”。
2. **第 2 关（分支投影与检索命中）**：Pi 只沿 JSONL 会话树的当前活跃分支投影消息链，切分支会把旁支规则留在树杈上；Letta 则区分常驻 `system/` 目录与需按需触发读取或 `recall` 的非核心区。
3. **第 3 关（预算装配与提示重编译）**：过长历史会在 `transformContext` 裁剪时被挤出预算；而在 Letta 文件记忆路径中，回合中途修改 `system/` 文件后，要等系统提示重编译完成，下一回合才会看到新快照。
4. **第 4 关（进入 Payload 并赢得注意力）**：即便原句确实进了本次请求，若夹在几万字工具报错堆栈中间，仍可能因注意力稀释被忽略——抓包核对原始请求 JSON 可在十分钟内精准定责。
