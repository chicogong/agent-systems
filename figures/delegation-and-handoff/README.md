# 委派的交接闭环：图的文字版

[返回章节](../../docs/concepts/delegation-and-handoff.md) · [可编辑图源](scene.excalidraw) · [SVG](diagram.svg) · [PNG](preview.png)

这是一张**概念图**，说明多执行者任务怎样从派发走向验收，不声称任何开源库完整实现了图中所有关口。

从左往右读：任务所有者给出目标、验收条件和批准完成的人。协调者据此制定带任务 ID 的合同，明确输入版本、范围、权限和回报要求。A 和 B 在各自的边界内执行；两条箭头把状态、证据、未知与副作用送回同一个对账关口。对账关口检查两份结果的版本、缺口、冲突和已发生的副作用。证据齐备且符合原目标时，任务所有者或其明确授权的验收关口决定交付；缺口或冲突时，虚线从验收关口接回任务合同，表示重新核定范围、输入、权限与回报要求，再补证、重新派发或转人工处理。虚线不表示重试一定安全或成功。

颜色区分所有者/协调、两份执行工作与验收；箭头文字和方向独立表达关系。图省略调度时序、存储、具体工具和协议。正文中的 LangGraph `Send` 固定源码示例只支撑“带特定输入派发、通过状态 reducer 汇合”的窄路径；任务合同、权限控制、冲突处理和业务验收属于应用设计。核对日期与静态/运行验证边界见[正文](../../docs/concepts/delegation-and-handoff.md)。
