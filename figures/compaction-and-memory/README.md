# 长会话不迷路：四种状态的分工与重装

[返回会话压缩与记忆](../../docs/concepts/session-compaction-and-memory.md) · [图源](scene.excalidraw) · [原尺寸 SVG（手机可放大）](diagram.svg) · [PNG](preview.png)

随着多轮对话和工具输出不断累积，如果把全部历史原样塞进下一次请求，轻则稀释模型注意力、漏掉早期约束，重则直接撞上上下文窗口上限。图中从左向右展示宿主如何把“持续增长的过程”拆进四条职责清晰的轨道：

1. **会话分支记录（Transcript）**：保留原始消息、工具回包与分支树（如 Pi 的 JSONL 记录），供审计回查并提取近期片段。
2. **压缩摘要（Compaction）**：当长度逼近阈值时，把早期长对话提炼成精简摘要，替代冗长原始日志进入后续请求。
3. **长期记忆（Memory）**：把跨任务通用的偏好、项目规范或提取出的事实单独存储（如 Letta 核心块或 Mem0 检索库），常驻系统提示或按需检索装入。
4. **进度检查点（Checkpoint）**：由执行引擎保存某一步的图状态快照（如 LangGraph），用于中断后续跑或分支回溯；若中断前已触发外部写入，恢复时须先核对外部实际结果。

右侧蓝色工作台说明：每一轮真正送给模型的输入，是从前三条轨道精选组装出的高信噪比材料，而检查点负责在宿主调度层把控续跑位置。
