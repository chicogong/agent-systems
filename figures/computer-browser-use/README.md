## 文字版

左侧画出两种看界面的办法。截图让模型看到整体布局，再判断按钮位置；DOM（网页结构）或辅助功能树则提供控件名称、角色和引用，例如“姓名输入框”。实际工具可以把两种办法配合起来使用。

沿着主箭头继续：模型根据当前界面建议点哪里、填什么。宿主检查任务范围、权限和界面状态，通过后才交给工具执行。检查没通过，就停下说明原因；重要动作怎样请人确认，要在任务和产品设置中提前安排。

执行后，再看界面并读取结果。比如任务要求填写姓名，就核对输入框里的值；要求保存记录，就再检查保存结果。绿色虚线把流程带回新一次观察：页面变了，坐标和控件引用也要更新。达到要求后结束；还没完成、且仍允许继续时，再选择下一步。

## 不同工具与图的范围

网页 DOM、操作系统辅助功能接口和浏览器调试协议 CDP 提供的信息各有不同；桌面工具能拿到什么，要看应用和接口。正文分别介绍 Anthropic Computer Use 的执行与坐标换算、Playwright MCP 的快照和浏览器配置、Chrome DevTools MCP 的检查，以及 Browser Use 的超时与动作检查。
