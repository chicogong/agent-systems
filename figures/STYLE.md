# 图稿设计原则（草案）

[返回图稿约定](README.md)

目标是让读者更快理解机制，同时让页面好看、易读。Pi 的分区卡片只是第一种样式，不是全书模板。先确定一张图要回答的问题，再选图形语法；不同项目可以有不同节奏、密度、字体和配色，但证据、可读性、可编辑性保持一致。

标题、编号和分区都不是必备组件。能靠页面上下文和图内标签读懂的图，不再额外加大标题或层级框；需要提示证据范围、状态边界或阅读方向时才使用。参考图主要提供线条、箭头、颜色和字体的视觉启发，不借用其业务结构。

## 按关系选图，而不是套皮

| 要解释的关系 | 优先尝试 | 避免 |
| --- | --- | --- |
| 调用先后与等待 | 时序图、泳道图 | 把并行事件画成一条必然的直线 |
| 状态变化与停止条件 | 状态机、分支图 | 只画成功路径 |
| 上下文、记忆或数据去向 | 数据生命周期、分层剖面、流向图 | 把存储位置与模型当前输入混成一层 |
| 模块依赖和控制边界 | 分层图、嵌套图、信任边界图 | 只有方框、没有说明箭头语义 |
| 多系统取舍 | 对照矩阵、同尺度小图 | 一个总榜或花哨雷达图掩盖证据缺口 |
| 反馈与恢复 | 环路图、事件时间线 | 让重试看起来像必然成功 |

同一个章节内保持视觉线索稳定，跨章节允许变化。一个项目的第二张图应增加新认识，不只是把第一张图重新着色。

## 字体与视觉节奏

可选 Excalidraw 的 Normal、Code、手写等字体。Pi 图采用 Normal / Nunito 标题和 Code / Comic Shanns 节点，是对用户参考图的回应，不要求 Codex、OpenCode、Letta 复刻。每张图通常不超过两套字体；中文、英文、代码混排时，以实际 SVG/PNG 中的回退字形和行距为准。标题、节点、注释要有层级，短标签留在图里，解释性长句放到图下。配色要服务类别或路径，不能只靠颜色传达结论。

可尝试轻微手绘描边（Excalidraw roughness 约 1）、约 2 px 的框线、约 3 px 的主路径箭头、Code 字体和高对比的浅色填充；这些是候选参数，不是所有图的强制主题。细虚线适合泳道、条件或未闭环路径，不能与主箭头同权重。每次导出后以实际显示尺寸检查字形、线宽、箭头和留白，再决定是否保留。

## 结构和语义

- 图里只写读图所需的机制、条件与边界；固定 commit、核对日期和“静态阅读/未运行”等来源元数据放在章节、图的文字版与来源台账，不烙进画布。这样换版复核时不会只改正文、漏改图片。
- 一张主图回答一个问题，按阅读顺序排布；框内写动作或状态，不堆完整段落。
- 实线表示当前图所描述的正常路径；虚线只用于反馈、条件分支或明确标为未完成的路径，旁边写出语义。实现图的证据等级须在图下说明。
- 用轻色背景分组，用稳定的边框色区分不同角色。颜色只做辅助，文字和箭头方向必须足以独立理解关系。
- 概念图与固定版本的实现图视觉上保持同一家族，但不混用“教学抽象”和“源码事实”。
- 分区卡片适合 Pi 这种“层与边界”的问题；别的系统可改用泳道、状态机、时间线、嵌套图或对照表。节点短句化，跨区箭头避开标题，连线标明调用、数据、事件或条件的语义。若一个箭头需要长解释，把证据放在图下文字版。
- 不追求统一的“AI 手绘感”。粗细、圆角、阴影、留白和强调色都应随图的用途调整；装饰不能盖过事实关系。

## 导出与验收

`.excalidraw` 是图源；SVG 用于 Markdown，PNG 用于视觉复核。修改后重新导出两者，检查标题、中文回退字体、边缘裁切、框内留白、箭头起止和 README 宽度下的可读性。图旁必须有等价文字说明。

Excalidraw MCP 交互画布目前会把文本强制显示为 Excalifont，因此非 Excalifont 图源与仓库 SVG/PNG **不能承诺字形一致**。交互画布用于探索和协作；对外发布的视觉结果以图源重新导出的 SVG/PNG 为准。若图必须在 MCP 里像素级一致，应另做 Excalifont 版本并分别验收，不能把两者称为同一次导出。
