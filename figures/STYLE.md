# 图稿视觉规范（草案）

[返回图稿约定](README.md)

目标是接近 Excalidraw 中清晰、克制的技术图：标题好扫读，节点像代码卡片，但仍保留一点手绘线条感。参考图仅用于字体和版式方向，不复制其内容或布局。

## 字体层级

| 层级 | Excalidraw 字体 | 使用位置 |
| --- | --- | --- |
| 页面标题、导语、图下注释 | Normal / Nunito (`fontFamily: 6`) | 保持中文段落清楚，不用大段手写字 |
| 节点标题、短标签、API/字段名 | Code / Comic Shanns (`fontFamily: 8`) | 让技术关系一眼可辨；中文由浏览器后备字形承接 |

一张图最多两套字体。优先 18–24 px 的节点文字和足够的留白；若为长句，移到图下文字版。中文与英文混排、箭头标签和换行处必须看实际导出，不能只看编辑器中的文本框尺寸。字体是视觉约定，不是对所有系统都使用同一套配色的要求。

## 结构和语义

- 一张主图回答一个问题，按阅读顺序排布；框内写动作或状态，不堆完整段落。
- 实线表示当前图所描述的正常路径；虚线只用于反馈、条件分支或明确标为未完成的路径，旁边写出语义。实现图的证据等级须在图下说明。
- 用轻色背景分组，用稳定的边框色区分不同角色。颜色只做辅助，文字和箭头方向必须足以独立理解关系。
- 概念图与固定版本的实现图视觉上保持同一家族，但不混用“教学抽象”和“源码事实”。

## 导出与验收

`.excalidraw` 是图源；SVG 用于 Markdown，PNG 用于视觉复核。修改后重新导出两者，检查标题、中文回退字体、边缘裁切、框内留白、箭头起止和 README 宽度下的可读性。图旁必须有等价文字说明。

Excalidraw MCP 交互画布目前会把文本强制显示为 Excalifont，因此采用本规范的 Code 字体时，它与仓库 SVG/PNG **不能承诺字形一致**。交互画布用于探索和协作；对外发布的视觉结果以图源重新导出的 SVG/PNG 为准。若图必须在 MCP 里像素级一致，应另做 Excalifont 版本并分别验收，不能把两者称为同一次导出。
