# 图的文字版：资料怎样进入这次回答

[返回概念专题](../../docs/concepts/context-vs-memory.md) · [图源](scene.excalidraw) · [SVG](diagram.svg) · [PNG](preview.png)

读书会的报名说明保存在文件中。助手回答报名要求时，先找到这份说明，读出相关内容，再交给模型。图把这段过程画成三部分：左边放着可用资料，中间挑选和读取，右边是模型这次实际收到的输入。

左边的四种来源各有用途：

- `transcript`（会话记录）保存聊天和操作历史。
- `summary`（压缩摘要）用较短的说明接续过去的工作。
- `memory`（长期记忆）保留跨任务使用的事实、偏好或状态。
- `retrieval` 对应外部知识的检索，从文件、数据库或网页找相关资料。

图中的“上下文装配”，就是从这些来源选取所需内容，再加上指令和新的输入，整理成一次模型请求。挑哪些历史消息、用哪份摘要、检索哪条记忆或文件，都由具体系统安排，同时要留意这次输入能容纳多少内容。

右边的“本轮模型输入”是整理后的结果。比如工具只返回了时间和地点，报名说明虽然仍保存在文件里，模型这次还缺这份材料，需要继续读取。

虚线列出可能使用的读取路径；具体系统可能只采用其中几种。Pi 的例子及固定源码位置见专题正文。

可在此目录运行 `python3 build.py` 重建可编辑图源，再用 excalidraw-agent 渲染 SVG 与 PNG。
