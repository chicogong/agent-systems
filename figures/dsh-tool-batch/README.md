# DSH：执行次序与结果提交

[返回正文](../../docs/systems/dsh/README.md) · [图源](scene.excalidraw) · [SVG](diagram.svg) · [PNG](preview.png)

假设模型依次提出 A、B、C 三个工具调用。图从左往右，区分“开始做事”“做完了”和“把结果交回”三个时刻。

程序先记录请求，再准备每次调用，检查输入与执行条件。需要询问用户时，先取得允许才执行。图中 `ask` 指需要询问；缺少审批通道时，该调用在这里被拒绝，不会交给工具执行。图里的 dispatch 指实际派发执行，无需询问的调用按自己的规则继续。

允许并行时，“有界池”限制最多同时执行几个工具。假设 B 比 A 快，B 先做完就先保留结果；图里的 ready 表示结果已经准备好。负责交回结果的 `commitReady()` 要等 A 就绪，再依次交回 A、B、C。于是完成顺序可以是 B、A、C，交回顺序仍是 A、B、C。

下方虚线提醒的是外部操作：B 若修改远端数据，修改可能在它交回结果之前就已发生。图中“有序日志 ≠ 外部世界串行”就是说，只排好了记录结果的次序，工具实际做事仍可能重叠；已发生的修改也要单独处理，这套提交次序没有提供事务回滚。

本图根据固定版的 `executeToolCalls` / `runGroup` 整理，版本和源码见[正文](../../docs/systems/dsh/README.md)，尚未采集实际运行记录。完整循环、其他插件、模式切换与取消细节留到后续阅读；运行安全和 MCP 画布与导出的一致性也未在此验证。

可在此目录运行 `python3 build.py` 重建原生图源；SVG 与 4× PNG 由同一固定 Excalidraw 原生导出器另行生成和实际检查。
