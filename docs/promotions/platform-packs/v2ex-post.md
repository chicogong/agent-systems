### 背景与痛点：我们为什么写这本书？

近一年来，大家都在做 Agent。但很多工程师从单轮聊天机器人转型到多步 Agent 时，往往都会遭遇几个非常诡异又极其昂贵的“鬼故事”：

1. **Token 账单与延迟雪崩**：  
   明明每一步模型只吐出几十个 Token 的工具调用参数，跑完一单 30 步的代码任务，累计发送的输入 Token 居然高达上百万。追查下去，发现仅仅是因为在 System Prompt 开头顺手加了一行 `当前时间：2026-11-26 15:30:00`，或者在上下文超出限制时写了一行看似无害的 `messages.pop(0)`。
   这一行写法直接废掉了现代大模型推理底座最核心的 **KV 前缀缓存（Prefix Caching）**，导致每一轮几十万 Token 的历史都需要全额重新计算注意力。

2. **把模型宣称的“做完了”当成任务验收**：  
   把写文件的工具权限交给模型，模型改完文件后工具返回了 `{"status": 200, "ok": true}`。模型看到工具返回成功，就直接对宿主汇报“已完成任务”。结果人类一跑测试，文件语法全是错的，甚至连核心用例都被模型顺手删除了。

3. **幻觉与死循环**：  
   面对一个测试报错，模型用相同参数反反复复重试了 20 次，直到烧光几百块钱额度触发超时硬熔断。

市面上现有的 Agent 教程大多走向两个极端：
- 一类是“玩具代码”：调两次 OpenAI API，拼几句 Prompt 就自称“手写 Agent 框架”，对生产环境必须面对的状态机推进、审批门禁、沙箱隔离、超时幂等一字不提；
- 另一类是“大而全的源码堆砌”：动辄几十万字通篇代码粘贴，缺乏直观的心智模型，读者很难看清架构全貌。

我们认为：**生产级 Agent 的本质绝非“Prompt 提示词工程”，而是一个在物理工程约束（上下文预算、显存缓存、时延、副作用爆炸半径）下运转的确定性分布式状态机。**

### 《图解 Agent 系统》的三个核心坚持

为了让这套系统工程真正好读、好懂、可动手验证，全书遵循了三条极其硬核的原则：

#### 1. 对标《算法图解》：40 组原生手绘 Excalidraw 矢量图
全书坚决不用 AI 一键生成的杂乱流程图，而是全部采用手工绘制的 Excalidraw 架构草图。一图剖析一个核心工程机制：
- 状态机推进与停机裁决（Loop & Stop Criteria）
- 前缀缓存经济学与击穿对比（Prefix Cache Mechanics）
- 记忆存储 vs 上下文预算漏斗（Context vs Memory Funnel）
- 沙箱环境设置与破坏半径管控（Sandbox Execution）

网页端所有图稿均可直接一键打开 Excalidraw 线上画板二次编辑，方便大家直接作为内部技术分享的架构参考。

#### 2. 绝无玩具代码：109 处源码全部锚定固定 40 位 Commit
我们拒绝架空理论，直接带你精读 16 个真实工业开源系统的源码：
- **Pi**：拆解轻量 Harness、会话分支与最小状态机；
- **Codex**：拆解意图审批流与沙箱隔离的两道物理防线；
- **Letta**：拆解分层持久记忆与重编译边界；
- **Qwen-Code**：面对上百个 MCP 工具时，如何用延迟加载 `tool_search` 守住前缀缓存稳定性；
- **OpenHands / Browser-Use**：剖析网页 DOM 树投影与自愈循环。

全书 109 处源码解析全部锁定在 GitHub 固定的 40 位 Commit 哈希和行号上，并通过自动化 CI 脚本每天检查，保证链接绝不漂移失效。

#### 3. 零外部依赖实验台 + 浏览器单步回放
很多同学没有海量 GPU，也不想绑定高昂的第三方云服务。
我们用 **纯 Python 3.10+ 标准库**（只用标准库，0 pip 外部依赖）编写了 6 组实验台：
```bash
# 3 秒在本地亲眼看到 96.1% 缓存命中 vs 0% 击穿的真实 Token 账单对比
python3 examples/prefix-cache/demo.py --mode layered_hit
```
在线站还搭载了交互式 **TracePlayer 状态机回放器**，无需本地搭环境，在网页上单步点按就能检查每一步的 Payload 流转与宿主快照。

### 分享一段干货：生产级 Prompt 排版的五层黄金律

在多步 Agent 里，输入与输出 Token 呈现极其悬殊的 `100:1` 倒挂（每一步都要把之前的全量历史重新发给大模型）。为了吃满现代推理引擎（vLLM、Anthropic、OpenAI）的前缀缓存红利，Prompt 必须遵循严格的**稳定度递减排版**：

```
Level 1 [全局恒定]   ── 角色准则 + 字母严格排序的稳定 Tool Schemas（缓存命中率 95%+）
       ↓
Level 2 [会话级稳定] ── 项目约定（AGENTS.md）+ 核心长期约束
       ↓
Level 3 [阶段级稳定] ── 达到 80% 水位线后一次性生成的定态阶段摘要
       ↓
Level 4 [步级纯追加] ── Append-Only 的历史交互流（绝不能用 pop(0) 滑动窗口打乱位移）
       ↓
Level 5 [瞬态队尾]   ── 秒级时间戳、单步预算消耗、动态状态观察挂在最末端
```

> 记住一条核心定律：**越稳定、跨步越不变的内容越靠左；越鲜活、每步都在变的内容越靠右。**
