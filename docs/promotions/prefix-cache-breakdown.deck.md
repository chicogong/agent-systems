# 100:1 的吞吐悬殊
## 为什么多步 Agent 会吞掉百万 Token？

- 普通问答输入输出比仅 2:1 至 5:1
- 多步 Agent 每执行一步，都要重新全量打包【系统指令 + 工具声明 + 全量历史 + 刚刚工具的观察结果】
- 跑完 25 步，累积输入 Token 高达 47.5 万，输出仅 4,000 Token！

```metric
累计输入 Token: 475,000 | 膨胀 100 倍
新生成输出: 4,000 | 仅占 1%
首字等待时间: 4.8s | 显存重复计算
```

# 生产级四层排版律
## 越稳定越靠左（靠前），越鲜活越靠右（靠后）

- **第 1 层（全局恒定）**：角色系统指令 + 字母字典序排序的 Tool Schema
- **第 2 层（会话稳定）**：项目工作区规范 (`AGENTS.md`) + 初始常驻核心记忆
- **第 3 层（阶段稳定）**：达到 80% 预算阈值后触发的阶段浓缩摘要块
- **第 4 层（瞬态鲜活）**：最近几轮动态对话、工具调用返回值与当前秒级时间戳

```metric

TTFT 首字延迟: 0.28s | 提速 17 倍
实测单步 Token 成本: -89.4% | 极客级优化
```
