# 帮我们试读三篇图解

[返回首页](../README.md) · [学习与应用](learning-and-practice.md) · [反馈入口](https://books.aimake.cc/feedback)

检验一张架构图有没有画明白，最好的办法不是背诵节点名词，而是面对一起真实的系统翻车事故时，你能不能像侦探勘查现场一样，一眼指着图上的某条链路说出：“故障卡在这里！”

下面准备了三桩高频的 Agent 故障悬案，无需安装软件，也不用运行代码。每次只需任选**一桩案子**，先读对应的图解章节摸清地形，再根据现场留下的运行日志或代码差异写下你的破案判断。请先独立写下第一版推理；如果你随后请常用 AI 搭档给了一句提示才豁然开朗，也请把“提示前后的理解变化”一并告诉我们——这能最直接地帮我们改进书中的图解与表述。

## 选一篇，读完换个例子试试

### A. 资料保存了，为什么回答时仍然缺信息？

- **侦查地图**：先读[上下文与记忆](concepts/context-vs-memory.md)，看清“外部长期存储”与“本轮喂给模型的输入窗口”之间隔着哪几道关卡。
- **案发现场**：团队知识库里明明完整存着三份活动文件，但在用户提问的这一轮，后台留下了如下运行快照：

```text
磁盘知识库文件：D1（周六 14:00）、D2（图书馆二楼）、D3（周五 18:00 前报名）
本轮检索工具返回：[D1, D2]
组装进模型的 messages：[SystemPrompt, D1 原文, D2 原文, User("参加活动要不要报名？")]
```

- **破案推演**：
  1. 站在模型此刻真正“看见”的输入窗口里，它能确凿回答哪些信息？哪块关键拼图压根没进屋？
  2. 如果严禁靠猜编造，宿主与工具接下来必须走图中的哪条回路，才能给出有据可查的回答？

### B. 工具已经接上，为什么还读不到资料？

- **侦查地图**：先读 [Skill、MCP 与工具权限](concepts/mcp-skill-tool-lifecycle.md)，理清“发现工具清单 → 加载作业规范 → 模型提议调用 → 权限拦截与服务端执行”的分工链条。
- **案发现场**：管理员刚给助手接好文档服务的 MCP 接口，现场调用日志却定格在下面这一幕：

```text
1. MCP 工具列表注册：materials.fetch 已对模型可见
2. Skill 提示装载：要求回答前必须拉取并核对一手出处
3. 模型输出 tool_call：materials.fetch({ "doc_id": "D3" })
4. 材料服务端返回：403 Forbidden — 当前会话令牌无权读取 D3
```

- **破案推演**：
  1. 对照工具生命周期图，前哪几步已经顺利走通，真正卡死在哪道边界上？
  2. “工具出现在模型的可用清单里”能说明它有权读取任意文档吗？为什么工程上必须把“工具可见性”与“数据访问权限”拆开校验？此时助手应该怎样如实向用户交代现状？

### C. Agent 说任务完成了，该查什么？

- **侦查地图**：先读[完成与证据](comparisons/completion-and-evidence.md)，看看为什么“模型自称改好了”甚至“测试跑绿了”都不能直接等同于可靠交付。
- **案发现场**：工程师要求编码 Agent **把接口超时改为 `5` 秒，并保持最大重试次数 `3` 不变**。几秒后 Agent 信心满满地汇报：“已完成修改，单元测试全部通过！”但拉开代码差异（`diff`）与测试日志一看：

```text
--- a/client_config.yaml
+++ b/client_config.yaml
-timeout_sec: 10
-max_retries: 3
+timeout_sec: 5
+max_retries: 0

执行验证：pytest tests/test_timeout.py -> 1 passed (仅断言 config.timeout_sec == 5)
```

- **破案推演**：
  1. 这份交付合格吗？你是交叉比对了现场的哪两份客观记录才揪出这个隐患的？
  2. 为什么测试全绿还会放过这种“顺手改坏邻居配置”的事故？要想真正守住交付边界，验收环节还必须补上哪项检查？
