# 上下文与记忆：资料怎样进入这次回答

[返回机制目录](README.md) · [可编辑图](../../figures/context-vs-memory/scene.excalidraw) · [PNG](../../figures/context-vs-memory/preview.png)

你电脑里有很多文件，但回答一个问题时，只会打开其中几份。Agent 也类似：系统可以保存大量资料，每次调用模型时，会挑出一部分交给它。这份**本次实际交给模型的材料**，就叫当前上下文。

所以，理解“记忆”先看两步：内容怎样保存，以及回答时怎样取出来用。下面这张图把这两步画开了。

![存储状态与本轮模型上下文的关系](../../figures/context-vs-memory/diagram.svg)

## 先看读书会的报名说明

在[读书会例子](agent-loop.md#先看一次正常完成)里，`D3` 写着报名截止时间。文件保存在知识库中；同学问报名要求时，助手先找到它，再读取原文，把内容交给模型，最后组织回答。

如果工具这次只返回日程 `D1` 和场地 `D2`，模型就拿到了时间与地点，但还缺报名说明。下一步应补读 `D3`。这个例子里的 `D3` 是一份外部资料；系统保存的用户偏好、历史消息和摘要，也各有自己的读取办法。

图左边是可用的内容，中间是挑选和读取，右边是模型这次实际收到的输入。虚线表示一条可能使用的路径，什么时候读取由系统决定。[图的文字版](../../figures/context-vs-memory/README.md)可以帮助你逐条看这些箭头。

## 把几个常见名字放到一起

| 名称 | 用大白话讲 | 回答时怎样用 |
| --- | --- | --- |
| 当前上下文 | 这次交给模型的指令、消息和资料 | 已经在本次输入中 |
| 会话记录 | 应用保存的聊天和操作历史 | 系统挑选需要的消息，可能只取当前分支或近几轮 |
| 压缩摘要 | 把一段长历史整理成短说明 | 系统将摘要放入后续输入，帮模型接着做 |
| 长期记忆 | 跨任务保留的事实、偏好或状态 | 按规则直接加载，或需要时检索 |
| 外部知识 | 文件、数据库和网页中的资料 | 通过读取或搜索工具取得相关内容 |

这些东西可能一起使用。比如系统先放入任务摘要，再读一条用户偏好，最后搜索两份文档。模型收到的是它们组成的本次输入，而不是整个数据库。

## 聊了很久，早先的要求怎样找回来

假设你先说“这次只写预览稿”，后来又聊了目录、配图和排版。全部消息仍保存在历史中，但这次输入只放了最近几条，早先的要求就可能被漏掉。

修正办法是回头查历史，找到“只写预览稿”，优先放入下一次输入。这里有四步值得分别查看：**有没有保存、有没有找到、有没有放入、回答有没有用对。** 找到资料后，还得留出输入空间；资料送入模型后，还要核对它给出的结果。

[上下文预算小实验](../labs/context-budget.md)把这四步打印出来，方便观察。同样大小的输入，先选最近消息和先找旧要求，会得到不同材料。它用字符数和固定规则做演示，读者不需要模型账号。真实产品常用 token 计算输入长度：文本先被分成小片段，再按片段计量；具体计量、搜索和压缩方法，要看它的实现。

## 在 Pi 代码里找这两步

Pi 的 `SessionManager` 从保存的记录中取出当前会话分支。请求模型之前，运行核心再依次执行 `transformContext` 和 `convertToLlm`，调整内容并转换成模型消息。

你可以把它理解为：**先选这段会话，再整理成这次要发送的材料。** [会话分支源码](https://github.com/earendil-works/pi/blob/898ab804050730e9dcefb4443875d5a932aa6a32/packages/coding-agent/src/core/session-manager.ts#L543-L582) · [请求前的处理](https://github.com/earendil-works/pi/blob/898ab804050730e9dcefb4443875d5a932aa6a32/packages/agent/src/agent-loop.ts#L380-L406)

这是本书所读固定版本的 Pi 路径。其他产品可能用数据库、文件或不同摘要办法，继续读[Pi 代码导读](../systems/pi/code-walkthrough.md)可以看清这个例子的具体分工。

## 用一个小变化检查理解

把报名说明换成一份集合通知：时间保存在文件里，工具这次只返回集合地址。先说清楚模型已经收到什么，再说明还要读取哪条信息。解释时用“查文件、选内容、交给模型”这些具体动作，比只说“它有记忆”更清楚。
