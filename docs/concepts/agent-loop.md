# Agent loop：从读资料到给出回答

Agent 可以理解成一个会**边做、边看结果、再决定下一步**的助手。你让它根据几份资料回答问题，它可以先读资料，发现缺了一份就继续找，材料齐了再整理回答。这种反复往前走的过程，叫 **Agent loop（运行循环）**。

这里有两种分工：模型负责建议下一步，运行程序负责调用工具、把结果交回模型，并决定是否继续。本书把这个运行程序叫作**宿主**。先记住这两个角色，再看图就容易多了。

![从任务目标到行动、观察与验证的概念循环](../../figures/agent-loop/diagram.svg)

图中的“模型决策”表示建议下一步，“观察结果”表示拿回工具执行后的输出或错误。完整的[图的文字版](../../figures/agent-loop/README.md)可以单独读；这张图是帮助理解的简化图，各产品的内部实现会不同。

## 先看一次正常完成

我们用一个虚构的读书会任务：**告诉同学这周活动的时间、地点和报名要求，每项注明出处。** 三份材料分别是：`D1` 写“周六 14:00 开始”，`D2` 写“图书馆二楼”，`D3` 写“周五 18:00 前提交报名表单”。

1. **先选要读的材料。** 模型收到问题和读取工具的说明，建议读取日程、场地和报名说明。这时模型知道要查什么，但原文还保存在文件或网页里，尚未交给模型。
2. **拿到材料，再往下做。** 宿主检查读取范围和参数，调用工具，把返回的原文交给模型。模型根据实际拿到的内容整理回答。三份材料可以分批读，也可以一次读完，取决于工具和宿主怎么安排。
3. **回答后对照一下原文。** 答复可以写成：“活动周六 14:00 开始 [D1]，地点在图书馆二楼 [D2]；请在周五 18:00 前报名 [D3]。”再检查时间、地点和报名要求是否都说对，出处是否对应。

沿着图看，就是**建议读取 → 宿主调用工具 → 拿回原文 → 整理并检查回答**。如果一开始就把三份原文都给了模型，它可以直接整理，省去读取工具这一步。循环的意义是根据任务需要继续做，而不是为了凑流程多调用几次工具。

现在只改变一件事：工具没有返回 `D3`。时间和地点仍能回答，报名要求需要补查。再把 `D2` 改成“只有场地网页地址”，助手就要打开网页找楼层，或说明目前还不知道。你可以用这两个变化，检查自己是否理解了“先拿到资料，再据此回答”。

## 用一条最小轨迹来读

```text
收到任务 → 准备模型输入 → 建议下一步
        → 宿主检查并调用工具 → 拿回结果
        → 继续做，或结束并检查成果
```

读代码时，先找三件事：**谁准备输入、谁执行动作、谁决定结束。** 模型提出调用只是建议；真正的文件读写和网页操作发生在工具里。结束时再看停止原因：任务完成、预算用尽、被取消和执行出错，需要分别处理。

图右侧的“验证”是本书建议的成果检查。具体产品可能使用测试、文件读回、人的确认，或其他检查方式。

想和 AI 一起读，可以用[陪读方法](../../book/frontmatter/reading-guide.md#和-ai-一起读)，先讲一遍读书会的过程，再换一份材料。想看程序怎么组织这些步骤，再选[本地小实验](../labs/first-agent-loop.md)：它用固定脚本代替模型，让你观察临时文件的读取、批准、修改和检查。

## 三种实现，各有侧重点

**Pi：把模型和工具串起来。** `Agent.prompt()` 启动循环，`runLoop` 安排模型请求、工具结果和后续输入。会话保存由外面的 coding-agent 应用负责。读它适合先理解运行核心，再看应用怎样管理历史。[Pi 导读](../systems/pi/README.md) · [`runLoop` 源码](https://github.com/earendil-works/pi/blob/898ab804050730e9dcefb4443875d5a932aa6a32/packages/agent/src/agent-loop.ts#L162-L320)

**mini-SWE-agent：把循环写得很短。** `DefaultAgent.step()` 先 `query()`，再 `execute_actions()`，随后把工具结果追加到消息中。外层 `run()` 根据消息和限制决定是否继续。代码短，适合跟着走一轮。[项目讲解](../systems/mini-swe-agent/README.md) · [循环源码](https://github.com/SWE-agent/mini-swe-agent/blob/04d809ceab9df28f9adaed044884180159172930/src/minisweagent/agents/default.py#L88-L157)

**OpenCode：把每次调用的进度记清楚。** 一次工具调用有待执行、执行中、完成和出错四种状态，对应 `pending/running/completed/error`。会话另有忙碌、待重试和空闲，对应 `busy/retry/idle`。例如，工具出错后，会话仍可能准备重试。排查时先看工具，再看整个会话，比较容易找到问题。[项目讲解](../systems/opencode/README.md) · [工具状态](https://github.com/anomalyco/opencode/blob/18ef3cc7c5a25b82114c953a80ccc09f4988f74e/packages/opencode/src/session/processor.ts#L216-L253) · [会话状态](https://github.com/anomalyco/opencode/blob/18ef3cc7c5a25b82114c953a80ccc09f4988f74e/packages/opencode/src/session/status.ts#L30-L48)

## 出错时，先看停在了哪一步

读取失败时可以补查，权限被拒绝时应说明受阻，工具超时后要确认动作是否已经发生。处理办法取决于出错的位置，下一轮该收到什么信息也随之改变。

mini-SWE-agent 会把格式错误交回下一轮，连续出错达到阈值后才停止；一般未捕获异常则会留下 `exit` 消息并重新抛出。[错误处理源码](https://github.com/SWE-agent/mini-swe-agent/blob/04d809ceab9df28f9adaed044884180159172930/src/minisweagent/agents/default.py#L100-L124) 这就是读停止条件的价值：知道程序为什么停，才能选择继续、重试或修正任务。
