# 按机制学习

[返回首页](../../README.md)

把大模型接进真实业务时，问题往往是按顺序冒出来的：刚跑通一次自动调工具，就会撞上多轮对话“忘掉最初约束”；刚用 MCP 和脚本把外部系统接进来，又得防止一条误判命令删库或越权；等单个助手忙不过来准备拆多 Agent 时，上下文交接、中途崩溃恢复与质量评测又成了新瓶颈。

机制篇不按产品说明书罗列功能，而是顺着这四道真实的工程关卡，把 14 篇核心机制串成一条可演进的知识脉络。每篇都先用直观模型讲清“为什么要这样设计、省掉这一层会出什么故障”，再落回开源项目的固定版本源码做对照。

## 一、循环与分工：先看清谁在推理、谁在动手

理解一切 Agent 系统的起点，是分清“模型提议下一步”与“宿主程序真正执行动作并决定何时刹车”。把这层边界立住，再去拆解五层系统栈和三种任务编排方式，就不会被层出不穷的新名词绕晕。

1. [Agent loop：从读资料到给出回答](agent-loop.md) —— 拆解模型与宿主（Harness）的往返闭环，看清工具状态机与刹车条件。
2. [模型、Harness、CLI、Skill 与 MCP：一项任务里的分工](model-harness-cli-mcp-skill.md) —— 用一次工单修复穿透五层架构，搞懂换掉其中任意一层会改变什么。
3. [Agent、工作流与多 Agent：安排任务的三种办法](agent-workflow-multiagent.md) —— 区分“步骤由谁决定”与“有几个执行窗口”，判断何时固定流水线完胜自主循环。

## 二、上下文与记忆：管好有限的注意力工作台

聊到第 30 轮突然把开头的硬约束忘得一干二净，通常不是因为磁盘没存聊天记录，而是因为“存下来了”不等于“这一轮装进了请求”，更因为塞进太多噪音会稀释模型注意力。

4. [上下文与记忆：资料怎样进入这次回答](context-vs-memory.md) —— 沿着“保存 → 查找 → 筛选装入 → 模型使用”四道关卡排查“失忆”根源。
5. [会话变长以后：保存记录、压缩内容、取回记忆](session-compaction-and-memory.md) —— 对照会话树分支、滚动摘要压缩、分层记忆与执行检查点四条工程路径。

## 三、权限、沙箱与扩展：给助手长出手脚，同时锁住爆炸半径

一旦允许模型读写文件、跑终端命令、连外部服务，或是直接操控图形界面，系统就必须在“放开能力”与“限制破坏面”之间划出硬边界——靠提示词叮嘱“小心操作”替代不了审批闸门与操作系统级隔离。

6. [审批、沙箱、工作目录：让助手按要求执行](approval-vs-sandbox.md) —— 为什么人工点了“批准运行测试”，底下依然需要目录边界与沙箱兜底。
7. [Tool、Skill、Extension、Package 与 MCP：给助手增加能力](extensibility-layers.md) —— 厘清五类扩展机制的职责边界、加载时机与信任成本。
8. [Skill、MCP 与工具权限：从查资料到完成任务](mcp-skill-tool-lifecycle.md) —— 追踪一次跨外部服务的任务中，方法加载、协议调用与读写授权怎样配合。
9. [沙箱执行环境：给代码一块合适的工作空间](sandbox-execution.md) —— 深入容器、微虚拟机与受限进程等隔离方案的工程取舍。
10. [Computer Use 与 Browser Use：让助手操作界面](computer-and-browser-use.md) —— 当系统没有现成 API 时，如何通过截图坐标或 DOM 树驱动桌面与浏览器。

## 四、协作、恢复与评测：让复杂任务稳得住、测得准

当任务跨越多步骤、多执行者甚至跨进程重启时，工程重心会从“单轮能不能跑通”转向确定性编排、子任务交接契约、幂等恢复以及可复现的验证闭环。

11. [Jev：让模型做判断，让程序安排后续动作](jev-and-system-one.md) —— 把高不确定性的语义判断留给模型，把确定性的流转和落盘交回代码。
12. [委派与交接：给几个助手分工，再把结果合起来](delegation-and-handoff.md) —— 用清晰的输入边界、权限范围与交付格式控制多执行者的协调通信税。
13. [中断、重试与恢复：把没做完的任务接着做](interruption-recovery.md) —— 面对超时、断连与崩溃，如何在不重复触发外部写操作的前提下安全续跑。
14. [观察、测试与评测：检查助手做得怎么样](observation-evaluation.md) —— 建立执行轨迹观测与回归评测集，避免每次改提示词或换模型都靠肉眼盲猜。

## 建议阅读路线

- **第一次系统入门**：建议按顺序读完前 5 篇（模块一与模块二），再加第 6 篇[审批、沙箱、工作目录](approval-vs-sandbox.md)，即可搭起完整的 Agent 核心心智模型；代码细节属于可选深入，不要求事先通晓某门编程语言。
- **边动手边验证**：读完第 1 篇后可以直接跑一遍[第一个机制小实验](../labs/first-agent-loop.md)，在不消耗模型额度的本地脚本里亲眼观察“读取 → 审批 → 修改 → 核对”的全过程。
- **带着场景选读**：想把这些机制迁移到日常研发、教学或团队协作中，可结合[学习与实践入口](../learning-and-practice.md)按需查阅后续专题。
