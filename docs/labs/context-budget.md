# 动手：存下的历史，不等于本轮可见上下文

[返回学习路线](../learning-path.md) · [上下文与记忆的机制解释](../concepts/context-vs-memory.md) · [第一条本地练习](first-agent-loop.md)

一个系统保存了完整聊天记录，为什么下一轮仍可能漏掉早先的重要约束？这一课不靠模型回答来猜原因，而是把**保存、选择、判读、验收**四个位置拆开观察。读完你应能用轨迹回答：记录还在不在、这轮有没有装入、遗漏后能得出什么结论、重新检索有没有真正恢复可见性。

本练习仅用 Python 标准库，不需要 API Key，不联网。记录是虚构的：一份草稿的最早约束是“本轮只允许生成预览稿；没有用户批准，不得对外发布”，后来积累了目录、来源、排版和学习路线的讨论。现在问题是：能对外发布吗？程序**不会发布任何内容**，也没有真实模型。`judge_visible()` 是只识别固定短语的规则判读器，不代表真实模型一定会给出这里的答案。

## 先预测，再跑三轮

从仓库根目录执行，使用 Python 3.10 或更新版本，无需安装第三方包：

```bash
python3 examples/context-budget/demo.py --mode full
python3 examples/context-budget/demo.py --mode recent
python3 examples/context-budget/demo.py --mode retrieve
python3 -m unittest discover -s examples/context-budget -p 'test_*.py'
```

运行前先预测：保存的 5 条记录会不会随着输入预算缩小而删除？同样 220 字符的预算，先检索旧约束再装配，会不会改变本轮看见的内容？

这里的“预算”是 Python `len(str)` 统计的 **Unicode 码点数**，下文简称字符数：规则、问题、记录 ID、正文、分隔符和换行都计入。它不等于屏幕上看到的字形数，例如 `e` 加组合重音可以显示成一个字形，却占两个码点。它也不是 token 数、UTF-8 字节数，不包含真实模型的输出预算、图像和工具 schema。中文与英文在真实 tokenizer 中的成本不同，不能用本例的数字换算某款模型的上下文窗口。

装配器先保留必要规则和问题，再逐条尝试完整记录；默认从最新的 `r5` 开始。某条装不下就跳过，继续尝试下一条，不把一条约束截成半句。检索模式把命中的旧约束 `r1` 提到候选顺序最前面，再用**同一个预算**重新装配。

| 模式 | 总预算／实际占用 | 本轮 `visible_ids` | 规则判读器结果 |
| --- | --- | --- | --- |
| `full` | 1200／248 字符 | `r5, r4, r3, r2, r1` | `do_not_publish`：看见明确的不得发布约束。 |
| `recent` | 220／212 字符 | `r5, r4, r3, r2` | `insufficient_evidence`：没有看见发布许可依据。 |
| `retrieve` | 220／217 字符 | `r1, r5, r4, r3` | `do_not_publish`：旧约束重新变得可见，`r2` 被挤出。 |

`full` 不是特殊的“全部通过”开关，只是默认预算足够大；给它小预算，同样会发生遗漏。`recent` 的“依据不足”也不是“允许发布”：这是模拟器主动选用的保守策略。若真实系统在缺少约束时自行补全许可，结论可能更危险，但本例没有测量这种模型行为。

## 看清四份信息各归谁

![保存来源经选择或检索后进入本轮输入](../../figures/context-vs-memory/diagram.svg)

这张概念图左边是系统可能保存或查询的来源，中间是选择与装配，右边才是一次请求的实际输入。某项“存在”并不自动产生一条“已装入”的箭头。本练习只实现其中的**固定历史 → 选择／字面检索 → 本轮上下文**路径，没有压缩摘要、外部知识库或长期记忆产品。图的[完整文字说明](../../figures/context-vs-memory/README.md)可单独阅读。

输出的四部分是一个最小状态账本：

- **保存来源 `stored_records`**：给读者看的完整原记录，在本次进程的元组里保存。不表示判读器收到全部记录，也不是磁盘持久化证明。
- **本轮输入 `context` 与 `visible_ids`**：实际传给判读器的字符串，以及装配器记录的 ID。装入不等于真实模型一定注意到、理解对或遵守它。
- **判读结果 `answer`**：判读器只依据 `context` 返回结果。没见到约束不表示来源里没有约束。
- **事后验收 `audit`**：回答之后对照完整历史，检查旧约束是否存着、是否可见、结果是否恢复。验收端的全量视角不能冒充判读器本轮的知识。

注意：完整 JSON 包含历史与验收字段，是为了让读者核对；代码并没有把整个 JSON 交给判读器。真实系统也要明确区分日志、数据库、调试面板与模型请求，不能因为日志里能查到一条信息，就断言模型已经看到了它。

例如 `recent` 的最后一个选择事件为：

```json
{
  "event": "select_record",
  "id": "r1",
  "characters": 36,
  "remaining_before": 8,
  "selected": false,
  "reason": "whole_record_does_not_fit"
}
```

这不是删除事件。`r1` 仍在 `stored_records`，只是剩余 8 字符装不下完整的 36 字符记录。接着看 `audit`：`critical_record_stored=true`，`critical_record_visible=false`。两者可以同时成立；“记得它曾经说过”与“这轮把原文交给判读器”不是同一个状态。

## 沿代码找到边界

打开 [`demo.py`](../../examples/context-budget/demo.py)，按四个函数看，而不是先读所有语法：

1. `retrieve()` 在保存来源里找字面字符串“用户批准”，只返回命中的记录 ID。它不是 embedding 或语义搜索；搜索词或来源措辞变化，都可能查不到。这里 `run()` 固定了搜索词，并没有从问题自动生成检索查询；单独改 `QUESTION` 不会改变命中的记录。
2. `assemble()` 先检查必要输入能否放下，再按候选顺序装完整记录。每次写下候选成本、剩余额度和取舍；预算紧张时，重新检索会改变谁被选中，而不会扩大窗口。
3. `judge_visible(context)` 只收到装配后的字符串，没有历史、检索 ID 或 `audit`。它只识别固定的禁止发布短语；空输入也不会暗中去全局历史找答案。
4. `run()` 在得到回答后才生成 `audit`，用完整记录核对；这是教学验收端的另一本账，不影响之前的回答。它也只用同一个固定短语判定来源约束，不是独立的自然语言事实评审。

因此，修复遗漏的动作不是“让判读器努力回忆”：来源仍在时，宿主可以重新查询、优先选择，并生成下一份输入。这与 [Pi 的资源／上下文装配](../concepts/context-vs-memory.md)、[Mem0 的检索接入](../systems/mem0/README.md)和 [Letta 的可编辑记忆](../systems/letta/README.md)有共同的机制问题，但本程序**没有调用或复现这些产品**；各产品的具体策略必须回到对应的固定版本案例核对。

## 改一个参数，用轨迹验收

先预测把新近选择的预算从 220 调为 248 会发生什么，再只改命令参数：

```bash
python3 examples/context-budget/demo.py --mode recent --budget 248
```

验收时不要只看“回答变了”。应同时找到：5 条记录仍保存、`r1` 已装入、总占用为 248 且不超过预算、回答为 `do_not_publish`。这说明**本模拟器**通过扩大预算恢复了约束；不是“窗口越大，真实模型必然越可靠”的证明。

再保持检索开启，把预算缩为 91：

```bash
python3 examples/context-budget/demo.py --mode retrieve --budget 91
```

这次查中了 `r1`，但必要输入先占了 56 字符，只剩 35 字符，装不下 36 字符的记录。装配器没有立即停止：它继续尝试后面的记录，最终装入恰好 35 字符的 `r3`，所以 `visible_ids=["r3"]`、总占用为 91，`critical_record_visible` 仍为 `false`。**查到、选中、装入、正确使用**是不同门槛，检索命中率不能单独代表最终答案质量。

最后试一个连必要规则与问题也装不下的预算：

```bash
python3 examples/context-budget/demo.py --mode recent --budget 10
```

输出 `budget_too_small`，`required_characters=56`，`context=null`、`answer=null`；CLI 退出码为 **2**，表示预期的输入拒绝。程序不会静默截断问题，也不调用判读器。已有测试同时覆盖正常选择、必要输入不足、旧约束遗漏、同预算重新检索、检索命中仍放不下、整条记录的边界，以及判读器不能偷读历史。

做完后用一句话回答：如果工具显示“已保存记忆”，还需要哪一条证据才能说“这轮模型看见了”？本课的答案是**查看这轮实际装配输入**，而不是存储成功提示。但在真实模型中，这仍只证明输入包含它；是否正确使用，还要用任务结果与反例另行验收。本例没有测 tokenizer、真实推理、记忆过期、冲突处理、权限、持久恢复或生产检索质量。
