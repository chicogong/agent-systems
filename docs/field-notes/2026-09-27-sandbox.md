## 五个主入口及上下游选择

1. 从 [Docker security](https://docs.docker.com/engine/security/) 入门：先资源视图和计量，再挂载/daemon 风险；下游读 seccomp，不先给读者一长串安全开关命令。
2. 从 [gVisor architecture](https://gvisor.dev/docs/architecture_guide/intro/) 理解 Sentry：下游读 security 与 compatibility；它可能作为容器运行时，不能把“Docker vs gVisor”写成互斥产品榜。
3. 从 [Firecracker 固定设计](https://github.com/firecracker-microvm/firecracker/blob/edb60617c31ebd610c530f67706ec5c79d4c2725/docs/design.md) 理解客体/VMM/宿主关系：下游待选专门测试环境再做实验。
4. 从 [Daytona Sandboxes](https://www.daytona.io/docs/en/sandboxes/#sandbox-lifecycle) 读 stop/pause/start/archive/delete：横向接 [E2B persistence](https://docs.e2b.dev/sandbox/persistence)，明确状态维度与环境类型而不拼默认时长排行榜。
5. 从 [OpenShell security controls](https://docs.nvidia.com/openshell/security/best-practices.md) 理解策略域与执行点：上游连接 Codex 审批，下游连接 browser identity 与外部副作用，不把厂商代理当业务授权本体。

## 后续可运行实验

优先一个纯假数据的本地教学实验，再择一真实 Linux 隔离环境：

- 仅 `cwd` 的进程仍可读取临时目录的兄弟“秘密”哨兵，说明 cwd 不是访问控制；数据全部合成，不尝试访问真实个人文件。
- 选择具体机制限制输入只读、输出可写、网络无外连；分别测允许写、越界读、子进程继承、超时清理与失败退出，记录平台/内核/运行时版本。
- 验收在执行环境之外检查产物；恶意输出即使 exit 0 也不通过，失败不自动改为有特权模式。
- 模拟远端接收动作后丢回执：环境销毁而远端记录仍在，复用当前 remote-effect 练习的数据与对账原则，不发真实请求。

实验代码尚未实现。标准库 policy simulator 不提供内核隔离；Docker/gVisor 实验须在已准备且明确授权的专门 Linux 环境执行，不能为了补篇幅在用户宿主安装高权限 runtime 或开付费云服务。
