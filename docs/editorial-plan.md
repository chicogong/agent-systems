# 成书与持续更新计划

[返回首页](../README.md) · [书稿构建](../book/README.md)

这本书采用“**固定版本的可核对剖面 + 可迭代的机制解释**”方式维护。PDF、GitHub 正文和可编辑图源从同一仓库生成；定时构建只产生审稿件，正式出版必须经过人工验收。

## 版本与完成定义

| 阶段 | 交付范围 | 完成判定 |
| --- | --- | --- |
| 预览样书 | 当前 38 个 Markdown 单元（含卷首与卷末）、16 组图；清楚标出静态源码范围 | 能重建 PDF，结构与图片检查通过；不足项公开列出 |
| 首版候选 | 八个机制主题均有独立解释、至少一个正常路径与边界路径；12 个系统现有局部剖面完成二次来源复核；至少四篇横向对照 | 非作者读者能沿机制路线读懂；术语一致；图、文字、源码定位逐项复核 |
| 正式发布 | 首版候选经过链接、许可、打印、移动端和外部试读审查 | 人工批准 tag 与 Release；发布 PDF、变更记录和已知限制 |

当前只达到**预览样书的本地构建**，没有达到首版候选或正式发布。尤其“12 个剖面已起稿”不等于 12 个系统完整审计。

## 内容缺口与收口顺序

1. **机制主线**：Agent loop、Agent/工作流/多 Agent、会话压缩与长期记忆已有首稿；仍须补中断与恢复、观察/测试/评测两篇，并深化多 Agent 交接协议。现有上下文、审批与扩展三篇作为样板。每篇必须给问题、最小例子、正常路径、失败边界、真实系统映射、证据等级及图的文字等价说明。
2. **代码导读**：逐篇检查现有系统剖面的“入口 → 状态 → 分支 → 副作用 → 结束/恢复”；Mem0、LangGraph 已补首稿，GPT Researcher 仍缺独立导读，不把大量源码粘贴进书里。
3. **跨系统对照**：现有两篇以外，补循环与停止、权限与恢复、完成判断。只比较已经核对过的同一问题；不做项目排名。
4. **来源与事实复核**：每个系统记录上游 URL、固定 commit、核对日期、范围、关键路径、许可和证据类型；对迁移/更名保留旧定位。核心结论至少一次独立复核；运行观察若没有环境和轨迹则继续标“未验证”。
5. **图与印刷**：每张架构图检查 `.excalidraw` 与 SVG/PNG 同源、箭头方向、文字裁切、缩小预览；PDF 检查封面、目录、字体嵌入、章节起页、图注、跨页断裂和实际 A4 打印。选定封面目前仅 1024 × 1536，屏幕审稿可用，印刷前须取得高分辨率或矢量母版；不把插值放大当作原生高清。

## 下一阶段：按机制深耕，不按项目堆目录

| 批次 | 研究问题与交付 | 合入书稿的门槛 |
| --- | --- | --- |
| 1 · 控制流 | 先补 Agent / 工作流 / 多 Agent 的界线，以及一次 Agent loop 的停止、重试、工具失败路径；以 Pi 为贯穿例子，再拿 Codex、OpenCode 对照 | 每条分支有固定代码定位；至少一张能讲清因果关系的图；明确哪些只是工程推断 |
| 2 · 状态与记忆 | 梳理上下文装配、压缩、会话记录、checkpoint、长期记忆及检索注入；覆盖 Pi、Letta、Mem0、LangGraph 的差异 | 分清“保存在磁盘”和“进入下一次模型请求”；给出中断/恢复或检索失配的边界案例 |
| 3 · 权限与扩展 | 梳理审批、执行隔离、工具注册、MCP、Skill、插件/Extension 的加载与生命周期；以 Pi 与 Codex 为重点 | 标出模型提议、宿主授权、实际执行三个动作的责任方；不以接口名推断安全性 |
| 4 · 评测与对照 | 补观察、测试、评测与完成判断；形成循环与停止、权限与恢复、记忆与上下文等横向章节 | 只比较已有来源覆盖的同一维度；不做无依据的性能或安全排名 |

每个新专题先写一句读者要解决的问题，再做最小任务轨迹；正文解释正常路径与失败路径，图表达关键状态和控制权，最后附固定源码定位与尚未验证项。图可以是流程、时序、状态图或对照，不强制统一布局；统一的是语义准确、箭头清楚、字体可读，以及可编辑图源和导出图一致。每个专题完成后请至少一位未参与写作的人复述图意，不能复述就修改图文。

优先顺序是**先把 Pi 讲透，再用其他系统验证比较维度**。Mem0、LangGraph 的代码导读已补首稿；GPT Researcher 仍待补齐，其他系统也需按固定版本二次复核。新章节达到合入门槛才进入书稿清单，避免周更 PDF 把半成品误当成正式内容。

## 维护节奏与负责人动作

- 每次 PR：来源和图文检查、自动 PDF 构建；审稿者检查改动页、所有含图页及前四页、末两页，标注字体、节点实际印刷字号、裁切、孤行、空页与链接问题。
- 每周：默认分支定时构建并保存 30 天审稿 Artifact；失败时修复构建，成功不等于内容已更新或可发布。
- 每月：抽查上游固定链接、项目新版本与许可变化，给每章留下“保持固定版 / 需要新版剖面 / 链接损坏”的结论；先开研究任务，不静默改写旧版事实。
- 每个候选版本：通读 PDF、抽查图源与导出一致性、用真实打印或印刷预览检查关键跨页，再由非作者读者试读；记录已知限制并人工批准 Release。

定时导出是**生产审稿件的机制**，不是定时发布。若要长期提供可下载的公开书籍，再单独设计经人工验收的 tag/Release 流程和存档策略。

## 每次更新怎样进入书

1. 在对应 Markdown 改正文和固定来源；有架构变化时同时改图源、SVG、PNG 与图的文字版。
2. 跑仓库检查；新增正式章节才加入 [`book/manifest.txt`](../book/manifest.txt)，不要靠文件名自动把未审稿草稿吸进书里。
3. PR 构建 PDF 并下载 Artifact 检查封面、受影响的章节和图页。每周定时构建检查默认分支是否仍能重建；它不自动更新书中结论。
4. 给变更标版本：错别字/排版属于修订；更换上游 commit 属于新的研究版本，保留旧版结论的范围说明。变更记录要写“新增、修正、仍未知”。
5. 准备公开版本时人工完成许可、外链、字体、第三方内容、隐私与印刷复核，再打 tag。Release 的 PDF 是不可变阅读快照，仓库 `main` 继续演进。

## 发布阻断项

- 任一图文结论缺固定来源且未标为推断/未知。
- 图片内容与正文或 `.excalidraw` 不同源，或者 A4/README 缩小后不可读。
- 自动构建失败、PDF 缺章/缺图/缺字、链接失效尚未解释。
- 许可不清、第三方材料未核对，或私人材料误入仓库。
- 没有至少一轮非作者读者反馈和打印实样检查。

外链、字体、仓库可见性与原项目状态会随时间变化；周期任务只发出待审查信号，不能自动把旧结论升级成“当前架构”。
