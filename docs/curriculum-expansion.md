# 从图解到会做：下一轮学习内容

[返回选题地图](program.md) · [四层学习路线](learning-path.md) · [当前完成度](roadmap.md)

全书当前最强的是**机制解释与固定源码切面**，最薄的是“让第一次接触 Agent 的人从一条可运行轨迹走到一个能验收的项目”。页数确实偏薄，但不能靠延长系统简介、增加空白或把热点项目排成名录来补。建议把 **160–200 页 A4 的下一版**当作编辑容量预估，而非发布门槛；每新增一章必须给出读者能做的判断、例子或练习、失败边界和验证方式。实际页数以构建结果为准。

这一取向参考 [Hugging Face Agents Course 的基础—框架—用例—最终项目安排](https://huggingface.co/learn/agents-course/unit0/introduction)及其[可观察性与评测单元](https://huggingface.co/learn/agents-course/bonus-unit2/what-is-agent-observability-and-evaluation)。这里只借鉴教学层次，不复制其材料或把外部课程当作本书已完成内容。

## 按读者能力补，而不是按产品名堆

| 读者迈过的门槛 | 现稿可读的入口 | 下一步应写/做 | 可验收的产物 |
| --- | --- | --- | --- |
| 认出“回答”和“动作”不同 | Agent loop、[第一条本地练习](labs/first-agent-loop.md) | 增加工具输入/输出、失败观察、停止条件的逐步讲解；用一页图文解释消息列表怎样成为本轮模型输入 | 能用自己的话复述一轮：提案、宿主许可、工具结果、下一轮输入、终态检查 |
| 接入能力但不越权 | 五层职责、MCP/Skill 生命周期、Codex 案例 | 做一个只读本地工具，再加入写入闸门；逐项对比工具 schema、Skill 指令和 MCP 接入 | 可运行的最小工具及拒绝、路径越界、坏参数测试 |
| 分清保存、可见与恢复 | 上下文/记忆、[固定输入预算练习](labs/context-budget.md)、压缩、LangGraph/Letta/Mem0 | 从内存选择扩展到存储读回、检索未命中和冲突事实；保持来源、选入与实际请求三个观察位置 | 一张状态账本：存了什么、本轮给了模型什么、能从哪里恢复 |
| 处理真实副作用 | 审批/沙箱、[回执丢失实验](labs/remote-effect.md)、权限/恢复对照 | 把内存模拟升级为可故障注入的本地 HTTP 服务；分别测试超时、迟到、重复键、查询滞后 | 事件轨迹、服务端收据和“已做/未做/未知”结论，不能只看 Agent 回复 |
| 交付可验证任务 | 委派、观察评测、完成判断 | 用“查三份资料并写摘要”做贯穿案例：任务合同、来源卡、工具轨迹、引用核对、失败恢复、人工验收 | 可重跑的任务与小型评测集；包括至少一个反例和成本记录 |

这些是有依赖的教学台阶。每个练习应提供“复制命令→预测→运行→读结果→改一处→验收”的短路径；真实 API 或付费账号只能放在可选进阶，不作为入门前提。现有练习都是**确定性教学模拟器**，不是模型驱动的 Agent；要增加真实模型版，必须单独说明 provider、费用、隐私与不确定输出的测试边界。

## 下一波系统，只补已有章节解释不了的取舍

2026-09-27 已补入 DSH 服务/工具批次、Hermes 知识维护，以及沙箱、Computer／Browser Use 执行面专题，并以[不可信观察与假完成练习](labs/evidence-contract.md)连接宿主许可和证据核验；具体验收范围以[路线页](roadmap.md)为准。下一波先做本地 HTTP 故障、持久化读回和带冲突的贯穿摘要任务，再选择下列新增系统。不因 CLI 名录更长而压缩入门练习。

1. **Gemini CLI：** 官方[策略引擎文档](https://github.com/google-gemini/gemini-cli/blob/main/docs/reference/policy-engine.md)可作为“工具许可为什么不是提示词”的公开入口。先固定源码版本，核对规则优先级与调用点；不把文档写成当前版本的完整实现证明。
2. **Cline：** 从[官方仓库](https://github.com/cline/cline)核对编辑器内的人工审批、差异预览与恢复记录。读者问题是“当操作发生在 IDE 里，宿主和用户各看见什么”；若证据不足，只写公开使用路径。
3. **OpenAI Agents SDK 或 Google ADK（二选一先做）：** 分别从[SDK 官方文档](https://github.com/openai/openai-agents-python/blob/main/docs/index.md)与[ADK 官方仓库](https://github.com/google/adk-python)选一条会话/交接/评测路径，和已有 LangGraph 章节按同一个问题对照。它们是构建应用的框架，不是与 Pi、Codex 并列的编码助手榜单。
4. **Aider、Goose、Pydantic AI、AgentScope 等：** 保留候选，只有能补一个独特的可证伪机制问题、定位固定代码并通过第二人复核，才进入系统篇。热度和 Star 数不是收录条件。

对每个新系统，先做“读者问题→固定版本→3 个关键源码位置→正常/失败两条路径→图/文字版→来源二审”，再考虑入 `book/manifest.txt`。开放阅读站可先发布已审正文；网站与 PDF 的发布快照须注明版本，不要把预研写成已验证架构。

## 页数与印刷的顺序

先完成上表前三个学习台阶和贯穿案例，再整书重排并统计 A4 实页。图要在最终页面大小读得清，不用图片占页补厚度。达到内容与权益验收后，才锁定纸张和装订，请印厂给出书脊模板；页数、纸厚或装订一变，书脊都要重新计算。当前的印刷询价与样书约束见[印前询价简报](../book/print-proof-brief.md)。
