# 图解为主：理解路线与可选实践

[返回选题地图](program.md) · [现有四层阅读路线](learning-path.md) · [当前完成度](roadmap.md) · [样章验收 Issue #4](https://github.com/chicogong/agent-systems/issues/4)

**定位：一本看图理解 Agent 系统的书，不是一门必须完成编程作业的课程。** 当前书稿以机制图解、具体例子与固定源码切面为主体；五条实验可选。下面的小项目、代码骨架与真实模型适配是进阶候选，尚未交付，不阻塞图解内容的修订与传播。本页只管教学设计；当前覆盖与线上发布状态分别以 [roadmap](roadmap.md) 和[网站版本记录](https://books.aimake.cc/version.json)为准。

默认阅读路线是：**一个具体问题 → 一张必要的图 → 顺着箭头讲正常例子 → 一个能帮助辨别的反例 → 按需看源码或实验。** 不要求先安装环境，不把每章都写成审计清单。读者不写代码，也应该能从图文中获得完整解释。

## 1. 先确定读者能看懂什么

保留现有研究与图稿，用“本地资料助手读取材料、回答并给出出处”串起需要连续解释的例子。**这个案例是讲解线索，不是必须构建的六阶段项目。** 不强迫 Pi、Codex、Hermes 等章节套用同一布局，也不把全书改成框架安装手册。

图文入口面向想理解 Agent 的读者，学生、非技术使用者和开发者都可进入，年龄或职业不是门槛。只有选择运行实验时才要求 Python 基础；工程读者可直接跳到固定源码与设计取舍。三种深度按需选择，不把运行代码设为看懂图解的前置条件。

阅读效果用一个新的小例子检查，而非必须提交代码。读者应能：

- 沿箭头说清一个正常任务：谁决定下一步、谁调用工具、结果怎样回来。
- 用日常例子分清上下文、记忆、工具、Skill 与 MCP，不只复述名词。
- 找到图中的关键取舍，解释一项条件改变为什么会让路径或结果不同。
- 想进一步核对时，知道去哪个系统的哪条源码路径；不要求安装全部产品。

读图理解、独立实现与真实模型运行是不同成果。选择实践路线时，再用新材料验收读者的工具、循环与引用核验；不能仅凭离线脚本宣布掌握了模型驱动行为。

## AI 陪读：用现有助手展开理解

默认图解路线增加一个可选的学习搭档，不把练习重心换成“让 AI 帮我完成全部作业”。读者先看图与正常例子，自己解释一个关系，再请 AI 帮忙找卡点、换个例子检查；想追代码时才进入固定源码。操作与唯一的通用开场放在[阅读指南](../book/frontmatter/reading-guide.md#和-ai-一起读)，这里不复制一套提示词。

首批用 Agent loop、职责分工、上下文与记忆三篇试读，检查“读图 → 自己解释 → AI 提示或追问 → 新例子判断 → 留下一张理解卡片”是否足够轻量。读者卡住时先给小例子；读懂即止，不规定聊天轮数、打卡天数或得分。移开 AI 后的新例子用于观察理解，不把 AI 自评当验收。

先使用普通段落、可复制材料和图的文字版，覆盖网页、GitHub、PDF 与离线 Markdown。不同助手的附件能力和联网能力不作统一承诺；书不要求某个品牌或额外付费。后续若需求明确，再考虑网页的“复制本节材料”快捷方式；内置聊天、学习者账号、上传私人笔记和自动评分暂不建设。英文试读可复用同一方法，但材料与图需对应译稿版本，不能靠即时翻译代替已审英文图文。

对外可以选一个自愿公开的学习例子：原图的一项关系、读者自己的解释、改变条件后的判断、对应章节链接。它展示内容怎样帮助思考，不把私人聊天截图、AI 表扬或尚未测量的效果当宣传证据；渠道与具体待发布稿仍放在私人方案仓库。

## 2. 可选进阶：一个小项目串起能力

首批材料拟用三份自写、明确虚构的读书会资料：日程、场地、报名说明。首问是“什么时候、在哪里举行，是否需要报名？分别给出出处”。随后增加旧版通知、缺失来源与新一场活动，避免读者先理解复杂业务才能学习机制。材料只来自随书目录，不访问私人笔记、真实账号或任意网页。

下表只适用于**选择动手的读者**，不是书的必读顺序，也不是六章必须先全部实现的工期。先看到正常成果，再拆开实现；必要的目录约束从第一步就生效，不以降低保护换取成功体验。

| 台阶 | 读者真正做什么 | 留下的成果 | 进入下一步前检查 |
| --- | --- | --- | --- |
| 先体验 | 运行参考助手，打开回答和来源，对照一条完整轨迹 | 第一份带出处的回答 | 能指出问题、工具结果和回答的位置；知道当前是否使用了真实模型 |
| 拆开循环 | 在提供的骨架里实现 `read_material()`，再补工具结果回填与继续/停止分支 | 自己实现的只读工具和最小循环 | 换材料 ID 仍可工作；不得偷读回放中尚未返回的材料 |
| 管理上下文 | 增加资料，补检索与输入选择；观察旧记录保存、命中但没装入的差别 | 可解释的本轮输入与来源选择记录 | 用同一预算比较正常与遗漏；指出事实缺失在哪里，不只看回答是否流畅 |
| 接入能力、控制动作 | 把已有读取工具接到本地 MCP；给输出工具加许可与目录约束，再加载一份 Skill 操作说明 | 同一助手的接入、拒绝与获准写入路径 | 工具发现不等于执行；Skill 正文说明不等于授权，产品配置例外另查；取消后停止发起新动作 |
| 验收与恢复 | 补来源核验、保存进度与读回；处理一份坏引用和一次中断 | 回答、证据表、可恢复状态及未完成说明 | 原文存在不等于解释正确；会话恢复不等于撤销或安全重做外部动作 |
| 对照与迁移 | 选择一条 Pi、Codex、Hermes 等源码路径，换材料完成同类新任务 | 一份架构映射和独立提交的实现 | 能解释教学程序与真实系统的共同问题及不同边界，不宣称复现整个产品 |

MCP 接入前先实现普通 Python 工具；首次不让读者同时处理 SDK、协议传输与工具逻辑。MCP 课应真实跑通本地工具发现与调用，并单列依赖与支持版本；若只展示手编事件，必须标为协议示意，不算接入完成。Skill 使用同一资料核对任务，不设计一个泛化的插件平台。

线程、锁、HTTP 服务关闭、分布式幂等和多执行者协调进入进阶。持续记忆先做一次专用学习目录的保存与读回，再讲冲突和重启；不另加一条与主项目无关的持久化实验来补页数。

## 3. 三篇图解样章：能独立阅读，也能串起来

[Issue #4](https://github.com/chicogong/agent-systems/issues/4)跟踪三篇样章的学习效果。每篇先讲正常机制，再回答困惑；可复用同一资料助手例子，但不要求读者完成上一篇代码。问题驱动不等于每篇都以失败或风险开场。

| 样章 | 现稿复用 | 看图能理解什么／可选动作 | 一项理解判断 |
| --- | --- | --- | --- |
| 记忆已经存了，为什么还是忘？ | [上下文机制](concepts/context-vs-memory.md)、[上下文实验](labs/context-budget.md)、Letta/Mem0 切面 | 跟一条旧事实走过保存、召回和请求；选做输入选择 | 能区分保存、召回、装入、正确使用；冲突规则不能简化为日期越新就一定正确 |
| MCP 已经接上，为什么仍不能执行？ | [职责分工](concepts/model-harness-cli-mcp-skill.md)、[MCP/Skill 生命周期](concepts/mcp-skill-tool-lifecycle.md)、审批机制 | 沿一项正常调用区分工具接入和获准执行；选做本地接入 | 换一个工具名和输入仍能定位发现、选择、校验、许可、执行中的失败点 |
| Agent 说完成了，怎样证明？ | [循环实验](labs/first-agent-loop.md)、[证据实验](labs/evidence-contract.md)、[完成对照](comparisons/completion-and-evidence.md) | 读懂从资料到带出处回答的过程；选做读取工具与引用核验 | 能对照来源解释一次回答是否满足目标，不因工具成功或语言流畅就判完成 |

**先制作第三篇的图解入门部分。** 暂题：“从资料到答案：一次 Agent 任务怎样完成”。一张任务轨迹图、一段具体例子，先走通正常过程，再指出回答与完成之间的核对位置；代码与实验作为可选延伸。先打磨可独立阅读的图文样章，不先搭完整课程框架。

图解样章的完整，是读者不运行程序也能理解问题、关系与取舍。它应有正常例子、必要的图、等价文字和一个轻量理解题；只有提供动手入口时，才另检查命令、代码与独立答案。

## 4. 可选练习要做好，不扩大成主任务

每课围绕同一个可见产物推进：**跟着完成 → 补全一小段 → 换一组输入 → 独立完成同类任务**。先给目标、前置条件和正常成果，再介绍为完成任务必需的机制；失败反例紧接对应能力，不在第一课集中列完所有风险。

- **跟着完成：** 给一条确定可运行的路径、预期输出和遇错时的检查位置；不要求盲读整个实现。
- **补全一小段：** 明确可改的函数、输入/输出、不可绕过的合同与公开测试。先补工具，再补循环，避免一次留空多个陌生层。
- **换一组输入：** 换材料内容、ID 与问题，测试读者实现，而不是换作者预设模式。包含正常新任务和一项本课相关的失败输入。
- **独立任务：** 只给合同、材料、评估条件；不给相同任务的填空步骤。允许多种合格实现，不按某一种句式判自然语言回答。

提示分成“观察位置 → 接口或不变量 → 最小代码方向”；参考答案移到独立答案页或答案目录，不紧接题目。网页可折叠提示，但 PDF 与普通 Markdown 也必须能在翻到答案前完成任务；不能依赖折叠效果防止提前看到答案。

自动测试同时检查参考实现与**读者待补实现**。未完成骨架的指定测试应失败；每补一步可观察对应测试转绿；完整参考实现应通过。需用故意错误的实现证明测试能抓住硬编码、忽略新输入或漏回填，不只证明作者程序能运行。可新增测试输入，不把隐藏判分规则当作教学效果。

机器检查引用 ID、片段、允许路径等结构条件；回答是否忠实、冲突是否解释清楚仍需任务特定评估和人工核对。测试通过、学生理解与用户接受分别留记录。

## 5. 回放与真实模型必须说清楚

离线模式用于零费用起步和稳定调试，但名称统一为**教学回放**，不是“真实 Agent 无账号版”。手编调用注明是合成轨迹；未来若收录真实模型采样轨迹，需标注采样版本、日期、许可和脱敏范围，不能把合成内容包装成真实记录。

回放与真实模型复用工具、宿主、消息表示和验收入口，只有提案来源不同。回放检查请求中预期的工具结果，再播放后续响应；不能绕开读者实现直接输出完整答案，也不能因回放可重跑就推断真实模型总会走同一路径。教学消息格式不是任一 provider API 的原样规范，适配层必须说明差别。

离线迁移题随新材料提供对应的回放夹具，用来检查读者的工具与循环是否适配新输入；它不具备理解任意新问题的能力。检查器必须抓住学生代码硬编码旧材料、漏读来源或没回填工具结果，不能只比较回放预写的答案。自由自然语言提问属于真实模型路线，不能用自动选择预设轨迹冒充模型决策。

真实模型接入作为可选进阶：首次只支持一种经核对的接口，另列模型/SDK 版本、密钥环境变量、费用上限、请求/步数预算和资料外发说明；不把密钥写入命令示例、日志或阅读包。输出按来源与行为合同核验，不固定回答原文或调用顺序。保存经过脱敏的实际输入/输出，并区分一次采样观察与稳定性质。

未接真实模型的读者应能解释“哪部分由宿主确定、哪部分在真实使用中交给模型决定”，但不能据此宣称已验证真实模型选择工具、生成答案或抗攻击的能力。

## 6. 内容架构与现稿迁移

默认入口以图解顺读和按问题跳读为主，保留现有机制、源码与对照。实践入口独立标为可选，不先推倒全书；正文仍只维护一份：

- 三篇图文样章优先修订现有机制与对照正文，不另复制一套；拟新增 `docs/tutorials/local-assistant/` 仅用于可选实践正文与独立答案页。
- 拟新增 `examples/local-assistant/`：同一项目的 `materials/`、`starter/`、`solutions/`、`tests/` 与 `replays/`；只针对本书需要，不造通用课程框架。学习者产物写入专用目录，不覆盖参考材料或真实仓库。
- `docs/concepts/` 继续解释机制；`docs/labs/` 明确定位为独立机制小实验；`docs/systems/` 保留固定源码切面；`docs/comparisons/` 连接同题取舍。源码篇标出它承接哪个学习问题，初学者一次只选一个系统。
- 样章代码、图文与验收完成后才调整 `book/manifest.txt`；再同步 README、阅读路线、GitHub 目录、网站、PDF 和 Markdown 包。学习路线与完整书序可不同，但不能发布一个还不能走通的“从零开始”承诺。

## 7. 实施顺序与验收

1. **先打磨图解。** 修订首篇的正常故事、图与简短解释；不先搭六章、provider 插件、持久化与 HTTP 扩展。
2. **校准理解与展示。** 看图能否复述关键关系、例子是否帮助理解；核对来源、导出和实际展示尺寸。技术与 Agent 冷读能找问题，不替代真人理解反馈。
3. **形成三篇独立样章。** 补上下文、MCP 与完成证据的图文入口。已审且已上线的内容可另做独立导读，不能因可选课程未完就暂停传播；投稿仍需单独确认。
4. **按反馈补少量实践。** 按 Issue #4 的目标开展真人试读；人数是本轮执行目标，不是出版标准。先检查能否解释图中的新例子；有明确动手需求时，再实现小项目的一段。不要用一套庞大作业体系替代图解质量。
5. **再合稿与发布。** 调整入口和书序，检查手机版网页、GitHub、离线 Markdown 与 PDF；样章验收不等于整书正式出版。印前、权益、非作者整书终审仍由 [Issue #1](https://github.com/chicogong/agent-systems/issues/1)跟踪。

图文试读先记录：读者理解了哪个关系、卡在哪条箭头或术语、换一个例子能否解释。仅对选择编程实践的读者，再记录启动、补全与新输入结果。公开反馈不收集账号、密钥或私人资料，不承诺人人在固定分钟数内完成。

本方案借鉴 [Diátaxis 的学习导向教程](https://diataxis.fr/tutorials/)对有意义操作、可见成果与小步推进的要求；教程不等于面向已有能力者的 [how-to](https://diataxis.fr/how-to-guides/)。按 [Teaching Tech Together 的逆向课程设计](https://teachtogether.tech/en/index.html#a-lesson-design-process)，先定义能力验收，再安排练习依赖与衔接正文。这里是编辑设计选择，尚未经过本书读者效果验证。

1. **Gemini CLI：** 官方[策略引擎文档](https://github.com/google-gemini/gemini-cli/blob/main/docs/reference/policy-engine.md)可作为“工具许可为什么不是提示词”的公开入口。先固定源码版本，核对规则优先级与调用点；不把文档写成当前版本的完整实现证明。
2. **Cline：** 从[官方仓库](https://github.com/cline/cline)核对编辑器内的人工审批、差异预览与恢复记录。读者问题是“当操作发生在 IDE 里，宿主和用户各看见什么”；若证据不足，只写公开使用路径。
3. **OpenAI Agents SDK 或 Google ADK（二选一先做）：** 分别从[SDK 官方文档](https://github.com/openai/openai-agents-python/blob/main/docs/index.md)与[ADK 官方仓库](https://github.com/google/adk-python)选一条会话/交接/评测路径，和已有 LangGraph 章节按同一个问题对照。它们是构建应用的框架，不是与 Pi、Codex 并列的编码助手榜单。
4. **Aider、Goose、Pydantic AI、AgentScope 等：** 保留候选，只有能补一个独特的可证伪机制问题、定位固定代码并通过第二人复核，才进入系统篇。热度和 Star 数不是收录条件。

对每个新系统，先做“读者问题→固定版本→3 个关键源码位置→正常/失败两条路径→图/文字版→来源二审”，再考虑入 `book/manifest.txt`。开放阅读站可先发布已审正文；网站与 PDF 的发布快照须注明版本，不要把预研写成已验证架构。

## 页数与印刷的顺序

先验证图解与现稿衔接，再调整必要的书序、统计实际页数。取消用某个页数区间衡量本轮完成度；图要在最终页面大小读得清，不用图片占页补厚度。达到内容与权益验收后，才锁定纸张和装订，请印厂给出书脊模板；页数、纸厚或装订一变，书脊都要重新计算。当前的印刷询价与样书约束见[印前询价简报](../book/print-proof-brief.md)。
