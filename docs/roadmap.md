## 下一轮内容收口

1. 补齐“中断、重试与恢复”和“观察、测试与评测”两个机制专题，并深化多 Agent 的任务拆分、交接和结果对账。机制章至少有正常路径、失败边界、真实系统映射和可读的图的文字版。
2. 按“入口 → 状态 → 分支 → 副作用 → 结束或恢复”二次复核现有系统篇；GPT Researcher 补独立代码导读。深度优先于新增项目数量。
3. 在现有状态/记忆对照外，补循环与停止、权限与恢复、完成判断；只比较两边都已核对的同一维度。
4. 为每个系统补齐核对日期、关键文件、证据类型及上游许可结论。无环境与轨迹的运行说法继续标为未验证。
5. 让非作者读者分别试读 GitHub Markdown、可携带阅读包和 PDF；检查移动端缩小视图、图源/导出一致性、A4 实页字号、断页、字体、封面分辨率与文字可访问性。

这些工作怎样进入仓库、成书与阅读包，见[写作与校稿方法](editorial-plan.md)。

## 发布门槛

| 阶段 | 完成定义 |
| --- | --- |
| 当前预览筹备 | 源稿、图稿及两种导出能构建；未核验范围如实标注。 |
| 首版候选 | 8 个机制主题、至少 4 篇横向对照，现有系统切面二次来源复核；非作者读者能沿机制路线读懂并复述图意。 |
| 公开预览 | 外链、许可、隐私、图文、Markdown 包、PDF 与移动端审查通过；明确已知限制后人工决定仓库可见性。 |
| 正式版本 | 候选内容经过完整通读与打印实样检查；人工批准 tag/Release，PDF 与 Markdown ZIP 成为同一个不可变阅读快照。 |

每周构建只产出 **30 天审稿 Artifact**，不会更新研究结论、自动提交生成文件或自动发布 Release。上游版本和外链变化由维护者另行复核；发布后旧剖面继续保留固定版本范围，而不是静默改写为新版事实。
