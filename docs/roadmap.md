## 内容架构

本指南有两条相互链接的阅读路径：

1. **机制路径**：从 Agent loop 到工具、上下文、记忆、权限、恢复、多 Agent 与评测。先说明问题和设计空间，再画出常见的状态与数据流。
2. **系统路径**：在固定版本上研究真实开源项目，用统一模板记录入口、循环、工具、状态、上下文、控制和验证。只在有证据时把模块标到图上。

横向对照页回答“同一个机制为什么有不同实现”，不复制各项目剖面的全文。

## 首批范围

| 阶段 | 交付 | 完成条件 |
| --- | --- | --- |
| 样章 | Agent loop、工具调用、上下文与记忆三篇；Pi、Codex、Letta 首批源码映射 | 每篇有可编辑图、文字版、固定来源与一处已核验实现 |
| 公开预览 | 权限、恢复、评测专题；OpenCode、OpenHands、mini-SWE-agent 剖面 | 两条阅读路径互通；图文经人工视觉复核；示例可运行 |
| 扩展 | Browser Use、OpenClaw、GPT Researcher、Qwen Code 等不同类型的 Agent；Aider、Cline、Goose、Gemini CLI 等对照卡 | 新系统能解释新的设计取舍，且来源版本与维护状态已核对 |

这不是完成清单。项目被列入候选不代表已完成调研或验证。

## 每篇正式内容的验收

- 读者能从图中说出关键组件、动作方向与停止/失败路径；图中没有无出处的实现细节。
- `.excalidraw` 能重新导出 SVG/PNG，文字无裁切；交互画布若提供，也单独目视核对。
- 源码结论带仓库、commit、文件/符号定位；运行结论附运行条件与结果。
- 图下有文字版，不依赖颜色表达唯一含义；专业词汇进入术语表。
- 原项目更名、迁移、归档或改变维护方向时，更新来源状态，不暗中把旧分析套到新版本。

## 发布门槛

公开前确定许可、审查私人内容与第三方材料、检查链接与图源、完成至少一轮外部读者反馈。发布后按固定版本维护剖面，新增项目先做候选卡，再决定是否深读。
