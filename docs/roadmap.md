## 下一轮内容收口

1. 对新补的委派、恢复、评测机制做非作者试读与故障/边界实验，特别验证实际多执行者交接；机制章的教学抽象不能冒充某一框架的完整保证。
2. 按“入口 → 状态 → 分支 → 副作用 → 结束或恢复”二次复核现有系统篇；GPT Researcher 补独立代码导读。MiMo Code 与 Kimi Code 还须运行层复核，深度优先于新增项目数量。
3. 在现有状态/记忆、循环与停止及命令关口对照外，补权限与恢复、完成判断；只比较双方都已核对的同一维度。
4. 为每个系统补齐核对日期、关键文件、证据类型及上游许可结论。无环境与轨迹的运行说法继续标为未验证。
5. 让非作者读者分别试读网页、可携带阅读包和 PDF；本轮电子版已完成图源/导出一致性、A4 实页、断页、字体和目录的校样，下一步仍须打印实样并升级约 131 PPI 的封面插画。像素密度通过不等于字可读。

这些工作怎样进入仓库、成书与阅读包，见[写作与校稿方法](editorial-plan.md)。

## 发布门槛

| 阶段 | 完成定义 |
| --- | --- |
| 当前预览筹备 | 源稿、图稿及两种导出能构建；未核验范围如实标注。 |
| 首版候选 | 至少 9 个机制主题、至少 4 篇横向对照，现有系统切面二次来源复核；非作者读者能沿机制路线读懂并复述图意。数量门槛不是质量验收。 |
| 公开预览 | 外链、许可、隐私、图文、Markdown 包、PDF 与移动端审查通过；明确已知限制后人工决定仓库可见性。 |
| 正式版本 | 候选内容经过完整通读与打印实样检查；人工批准 tag/Release，PDF 与 Markdown ZIP 成为同一个不可变阅读快照。 |

每周构建只产出 **30 天审稿 Artifact**，不会更新研究结论、自动提交生成文件或自动发布 Release。上游版本和外链变化由维护者另行复核；发布后旧剖面继续保留固定版本范围，而不是静默改写为新版事实。
