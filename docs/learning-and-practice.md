# 把所学用起来：学习、教学与工作中的 AI 实践

[选择阅读路线](learning-path.md) · [和 AI 一起读](../book/frontmatter/reading-guide.md#和-ai-一起读) · [Agent 循环图解](concepts/agent-loop.md)

先做一件小事：根据几份材料，给同学写一段活动说明。下面的读书会是虚构例子，可以用纸笔完成，也可以把材料交给常用的 AI 助手。无需注册产品、购买 API 或运行代码。

## 一组材料，一份看得见的成果

这是与[Agent loop](concepts/agent-loop.md)相同的资料任务。D1、D2、D3 是材料编号，方便标明每句话的出处。

| 来源 | 随书材料原文 |
| --- | --- |
| `D1` 日程 | 读书会在周六 14:00 开始。 |
| `D2` 场地 | 地点为图书馆二楼。材料未说明是否有停车位。 |
| `D3` 报名 | 参加读书会需要提前报名，周五 18:00 前提交表单。材料未提供表单链接。 |

任务是：告诉准备参加的同学，活动什么时候、在哪里举行，是否需要报名；每项注明出处。愿意的话，先自己写三四句话，再看参考回答。

> 读书会周六 14:00 开始（D1），地点在图书馆二楼（D2）。参加前需要报名，请在周五 18:00 前提交表单（D3）。材料没有给出表单链接，报名时还需要向活动方查询。

回答里的时间、地点和截止要求，都能回到原文。停车位有没有，则留作待确认信息。

现在回到[循环图](concepts/agent-loop.md)：助手根据任务找到材料，工具读取原文，模型收到内容后组织回答，再检查有没有漏项。如果一开始已经提供全部原文，就可以直接整理；需要继续查找时，再使用读取工具。

## 把方法带到你的场景

### 学生：把一份资料变成自己的理解

用这些材料做一张活动卡片，列出时间、地点和报名要求，再写两个想继续了解的问题。例如“需要带什么材料”放在待确认栏。

换成课程材料时，也可以用同样做法：用自己的话解释一个关系，标出原文位置，留下一项疑问。请 AI 换个例子或听你复述，再回到课本核对。作业与材料使用遵循学校要求，不上传同学信息或未获准分享的资料。

### 老师：从图解组织一次讨论

先请学习者整理一份活动说明，再一起找到每句话的出处。随后拿掉报名说明 D3，讨论已经知道的内容和需要补查的内容。

可以让两人互相检查，再共同解释图中“读取资料”的箭头。分组、时长和教学目标由老师结合课堂安排；学生使用纸笔也能参与。

### 工具使用者：做一份能交接的简报

把材料整理成三栏：已知安排、建议下一步、待确认问题。“活动周六开始”放在已知安排；“询问表单链接”放在建议；“是否有停车位”放在待确认。

交给同事时，对方就能知道哪些内容可以直接使用，以及还需要做什么。这个示例只整理文字。需要发送通知或提交报名时，再确认实际操作要求，并检查操作结果。

### 好奇与职业探索：留下一份能说明能力的作品

选一个愿意公开的小任务，例如整理活动资料、解释一个概念，或比较两份通知。留下原材料、第一版结果和一次修改，再写清你为什么这样改，哪些地方借助了 AI。

作品可以是一页 Markdown、一张能讲清楚的图，或一份带来源的简报。试过以后，可能会发现自己更喜欢教学表达、资料研究、流程设计或编程。再选一项能力深入，逐步积累经验；本书不承诺职位和收入。

## 留下一张轻量任务卡

先把任务要求写清楚，例如：

```text
目标：给准备参加的同学写一段活动说明。
材料：使用 D1、D2、D3 三份公开或虚构材料。
要求：说明时间、地点和报名方式，并标明出处。
动作：只整理文字，暂不发送或报名。
检查：对照原文，缺少的信息放进待确认栏。
```

换任务时，把这五行改成自己的要求，仍只使用公开、虚构或已获准分享的材料。使用 AI，可以附上材料和任务卡，先确认它收到的内容，再一起检查回答。真正操作文件或网页时，还要单独查看产品的权限和执行设置。

## 换一组材料再试

另一场虚构活动是周日 10:00 开始，在图书馆一楼举行，无需报名。分别重写日程、场地和报名三份说明，再整理成新的活动卡片。

完成后，对照新材料检查日期、地点和报名要求。补充建议单独写，缺少的信息具体列出。再请别人或 AI 挑一处可以改进的地方，比较修改前后的差别。

这组尝试用于帮助理解方法，本书没有做学习效果实验，也没有记录真实活动的操作结果。
