# 从公开预览到可出版版本：验收单

[返回首页](../README.md) · [当前状态与缺口](roadmap.md) · [写作与校稿方法](editorial-plan.md)

这是一张**重复使用的验收单**，不是当前版本的通过证明。完成状态只在[路线页](roadmap.md)更新。公开阅读、电子版定稿、送印和正式出版是不同决策；自动构建通过只能证明文件与部分结构正确。每次候选版都应固定一个 Git 提交，并把证据、审稿人、日期和遗留问题放到该候选版的审稿记录中。没有人工签收的项目不标“通过”。

| 门槛 | 需要留下的证据 | 放行标准 |
| --- | --- | --- |
| 内容完整性 | 与 `book/manifest.txt` 一致的目录、章节逐篇审校记录、术语与交叉引用表 | 章节有明确读者问题、可理解的因果链和失败边界；没有占位段落、互相矛盾的定义或目录遗漏。 |
| 技术准确性 | 上游固定 commit/官方文档、逐条关键主张的第二人核对记录；运行说法附环境、命令和结果 | 源码事实、文档声明、作者推断和未知分开；图上每条事实箭头能回到文本与证据。静态阅读不冒充实测。 |
| 教学可用性 | 非作者读者从零照做一条完整练习的记录；跨入门与已有经验读者的试读意见 | 读者能复述图意、完成练习、解释失败案例；关键术语不要求先知道书后章节。 |
| 权益与署名 | 原创图文的创作或授权记录、第三方素材/字体清单、许可与必要 NOTICE；作者最终确认 | 只发布有权发布的内容；引用、商标、上游代码与 AI 辅助素材的边界明确。CC BY 4.0 不自动取得第三方权利。 |
| 数字阅读 | GitHub 书序目录、网站页面与锚点、Markdown ZIP、PDF 链接/书签的自动检查和人工抽读 | 四种入口沿同一清单到达同一正文；桌面、窄屏、键盘与至少一种辅助技术可读；PDF 若未标记，则明确优先使用 HTML。 |
| 视觉与排版 | 含图页逐页校对、代码块与脚注抽查、封面/目录/正文/封底实页样张 | 无裁切、溢出、缺字、错页、模糊或难辨的箭头；代码与中文字体清晰，图在最终页宽下可读。 |
| 印前制作 | 印厂的成品尺寸、出血、色彩、纸张、装订、书脊模板及书面报价；按其规格输出的文件和打印实样 | 封面与正文分别按实际印厂模板验收；图片有效分辨率满足印厂要求，实体样书的文字、图和装订经作者签收。屏幕 300 DPI 导出不等于原素材 300 PPI。 |
| 版本与发布 | 候选提交、PDF/ZIP SHA-256、版本说明、勘误入口、发布/撤回责任人 | 固定版本可回溯；在线可替换预览与不可变正式下载地址分开；不是每周审稿 Artifact 自动上架。 |

## 推荐的候选版流程

1. 先合入已核对的正文、来源和图稿；从 `book/manifest.txt` 生成 [GitHub 目录](../book/CONTENTS.md)、网站、Markdown 包与 PDF，不手修导出物。运行仓库和公共站门禁。
2. 用候选提交号建立一份审稿记录。按上表从内容、来源、图意、数字阅读和权益逐项签收；至少一位非作者读者做冷读和练习复现。记录未解决项，而不是只写“已检查”。
3. 若制作实体书，先向印厂索取**其实际模板和报价**，再制作含出血的最终封面/封底/书脊与内页；拿实体样张回查。当前屏幕封面参考图和 A4 内文校样不能直接替代这一步。
4. 由作者单独批准电子定稿、仓库版本、网站更新与送印。发布时记录提交、SHA-256、渠道及反馈方式；发现严重错误能定位具体版本并发布勘误。

“可送印”只表示文件经过指定印厂的技术验收；出版资质、书号、合同和发行合规随发行地点与方式而异，须由出版方或合格专业人士另行确认。本清单不构成法律或印厂验收意见。
