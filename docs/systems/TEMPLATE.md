# 系统篇写作模板

> 复制本结构时删去提示，不要把未知内容写成已验证事实。

1. **先给一个任务**：用熟悉的事情说明这个系统能处理哪一类工作，先看一次正常过程。
2. **图与文字版**：提供可编辑源、SVG、PNG；正文说明每一步谁拿到什么、做什么、结果交给谁。
3. **讲清具体步骤**：少堆接口名。术语初次出现紧接中文解释，条件变化后说明怎样处理。
4. **可选源码深入**：沿一条路径讲入口、主要状态、工具执行和结束条件；关键位置链接到固定版本。
5. **说明取舍**：围绕一个具体问题对照另一种做法，解释收益与代价。
6. **来源和研究范围**：章末记录规范仓库、完整 commit、核对日期、许可和已读范围；说明源码、文档与运行记录各支持什么。
7. **核验和后续**：记录图稿与实际运行的检查结果，列出尚未检查的项目。长篇审查记录放在 `docs/reviews/`。

大系统先写一条有来源的具体路径，再逐篇扩展。图和关键说法对应固定源码或官方文档；虚构教学例子、推断和未运行范围如实标注。费用、隐私和批准提醒，放在相关操作之前。
