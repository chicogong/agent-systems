# 系统剖面模板

> 复制本结构时删去提示，不要把未知内容写成已验证事实。

1. **问题**：本篇只回答哪一个架构问题？为什么这个系统适合回答？
2. **版本**：规范仓库 URL、完整 commit、核对日期、许可和维护状态。
3. **图与文字版**：可编辑源、SVG、PNG；逐步说明正常路径、停止/失败路径和图未覆盖的范围。
4. **证据表**：每个关键箭头/模块对应固定版本的源码或官方文档；标明源码事实、文档声明、运行观察、推断或未知。
5. **设计取舍**：与至少一个系统对比同一机制，指出代价而非只列优点。
6. **核验记录**：本地导出与缩小预览是否检查；运行实验的环境、输入和结果；哪些仍未验证。
7. **后续问题**：下一篇应拆出的机制，不在本篇随意展开。

大系统优先写一条可定位的路径，再逐篇扩展；不从 README 的产品描述直接生成所谓“完整架构图”。
