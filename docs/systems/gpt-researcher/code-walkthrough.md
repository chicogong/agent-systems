# 代码导读：Hybrid 的两路上下文如何交给报告写作器

[返回 GPT Researcher 剖面](README.md)

想读代码时，跟着“根据手头材料和网页写一份技术调研”这个例子即可。先找收集资料的位置，再找材料如何整理，最后找写作器收到什么。

范围固定在 [`6f998577`](https://github.com/assafelovic/gpt-researcher/tree/6f998577d547b1e54ec662dac63583aa11e3b84b)：`ResearchReport` 是普通报告，`ReportSource.Hybrid` 是混合来源，`PromptFamily` 是提示模板。这里选择非 Granite 模板，调用者未指定 `source_urls`，也未提供写作外部上下文。下面按代码讲解，没有运行这项调研。[提示词家族选择](https://github.com/assafelovic/gpt-researcher/blob/6f998577d547b1e54ec662dac63583aa11e3b84b/gpt_researcher/prompts.py#L879-L903)

## 沿调用链走九步

1. **先准备研究任务。** `GPTResearcher.__init__()` 保存来源设置 `report_source`、`source_urls`、`document_urls` 和 `query_domains`，并建立记录已见网址的 `visited_urls` 与保存材料的 `context`；`context` 初始可以为空。随后，`conduct_research()` 把普通报告交给 `ResearchConductor.conduct_research()`，将返回的材料存入 `self.context`。只有 `report_type == DeepResearch` 且对应研究器存在时，才走深度研究分支。[构造状态](https://github.com/assafelovic/gpt-researcher/blob/6f998577d547b1e54ec662dac63583aa11e3b84b/gpt_researcher/agent.py#L138-L180) · [研究入口](https://github.com/assafelovic/gpt-researcher/blob/6f998577d547b1e54ec662dac63583aa11e3b84b/gpt_researcher/agent.py#L331-L401)
2. **`source_urls` 比 Hybrid 优先。** `ResearchConductor.conduct_research()` 先检查是否提供了特定来源 URL，随后才比较 `report_source`。所以传了 `source_urls` 的请求不会自动进入下面的 Hybrid 并发分支；要研究指定 URL 的行为，应另读 `_get_context_by_urls()`。在本文前提下，控制流落到 `ReportSource.Hybrid`。[来源选择](https://github.com/assafelovic/gpt-researcher/blob/6f998577d547b1e54ec662dac63583aa11e3b84b/gpt_researcher/skills/researcher.py#L144-L186)
3. **装载文档，安排两路收集。** Hybrid 有 `document_urls` 时用 `OnlineDocumentLoader`，否则从配置的 `doc_path` 用 `DocumentLoader`；若设置了 `vector_store`，还会把装载结果写入它。接着 `asyncio.gather()` 同时发起两次 `_get_context_by_web_search()`：一次传 `document_data`，一次传空列表。`document_data` 为空时，第一路并不会因此终止，见第 5 步的回退。[Hybrid 两路及可选写入](https://github.com/assafelovic/gpt-researcher/blob/6f998577d547b1e54ec662dac63583aa11e3b84b/gpt_researcher/skills/researcher.py#L172-L186)
4. **两路各自规划子问题。** `_get_context_by_web_search()` 中，文档和网页两路都会调用 `plan_research()`。规划函数先用首个 retriever（检索器）做初始搜索，再生成研究提纲；因此，使用文档这一路时，也要按检索器配置考虑联网。非子专题报告把原始 query 追加到子问题列表，再用 `asyncio.gather()` 并发处理这些问题。[规划时的初始检索](https://github.com/assafelovic/gpt-researcher/blob/6f998577d547b1e54ec662dac63583aa11e3b84b/gpt_researcher/skills/researcher.py#L50-L95) · [子问题执行与空结果](https://github.com/assafelovic/gpt-researcher/blob/6f998577d547b1e54ec662dac63583aa11e3b84b/gpt_researcher/skills/researcher.py#L362-L398)
5. **为每个子问题取得原文。** `_process_sub_query()` 收到非空文档列表时，直接从这些材料中提取相关内容；`scraped_data` 为假时，才调用 `_scrape_data_by_urls()` 搜索、取得网页，所以空文档列表也会走这条路。网页路径按 retriever 的 `requires_scraping` 选择重新抓取，或复用已带回的 `raw_content`。待抓取 URL 通过 `visited_urls` 去重，抓取结果也可以按配置写入向量库，然后交给上下文整理。[子问题的关键条件](https://github.com/assafelovic/gpt-researcher/blob/6f998577d547b1e54ec662dac63583aa11e3b84b/gpt_researcher/skills/researcher.py#L595-L606) · [URL 与正文的选择](https://github.com/assafelovic/gpt-researcher/blob/6f998577d547b1e54ec662dac63583aa11e3b84b/gpt_researcher/skills/researcher.py#L826-L935)
6. **原始材料在此变成“相关上下文”。** `ContextManager.get_similar_content_by_query()` 把页面列表交给 `ContextCompressor`。材料总字符数低于 `COMPRESSION_THRESHOLD`（默认 8000）且文档数不超过上限时，快路径直接格式化前几份文档；否则用拆分与 embedding 相似度过滤。整理后的文本包含 `Source`（来源）、`Title`（标题）、`Content`（正文），方便写作时引用和之后对回原文。[压缩入口](https://github.com/assafelovic/gpt-researcher/blob/6f998577d547b1e54ec662dac63583aa11e3b84b/gpt_researcher/skills/context_manager.py#L37-L64) · [两种压缩路径](https://github.com/assafelovic/gpt-researcher/blob/6f998577d547b1e54ec662dac63583aa11e3b84b/gpt_researcher/context/compression.py#L127-L188) · [上下文格式](https://github.com/assafelovic/gpt-researcher/blob/6f998577d547b1e54ec662dac63583aa11e3b84b/gpt_researcher/prompts.py#L554-L566)
7. **合并两路材料。** 每路先把非空子问题结果连接为字符串；本文范围内的 `PromptFamily.join_local_web_documents()` 再将它们包装成“local documents”和“web sources”两段，写到 `researcher.context`。开启 `curate_sources` 时，后面还会筛选来源、重新整理上下文。Granite 提示模板采用另一种拼接格式，需要按对应实现查看。[子问题汇总](https://github.com/assafelovic/gpt-researcher/blob/6f998577d547b1e54ec662dac63583aa11e3b84b/gpt_researcher/skills/researcher.py#L380-L398) · [本篇拼接格式](https://github.com/assafelovic/gpt-researcher/blob/6f998577d547b1e54ec662dac63583aa11e3b84b/gpt_researcher/prompts.py#L563-L566) · [Granite 覆写](https://github.com/assafelovic/gpt-researcher/blob/6f998577d547b1e54ec662dac63583aa11e3b84b/gpt_researcher/prompts.py#L756-L834) · [保存及可选筛选](https://github.com/assafelovic/gpt-researcher/blob/6f998577d547b1e54ec662dac63583aa11e3b84b/gpt_researcher/skills/researcher.py#L209-L241)
8. **把整理后的材料交给写作器。** `GPTResearcher.write_report()` 在本篇前提下把 `self.context` 交给 `ReportGenerator.write_report()`。写作器去掉字符串两端的空白，内容非空时才调用 `generate_report()`。随后，`generate_report()` 把上下文放入提示，请求 LLM 写报告；失败时换一种消息组织再试，再失败就记录异常并返回当前 `report`。拿到报告后，应用还需把事实和引文对回原文。[写作交接](https://github.com/assafelovic/gpt-researcher/blob/6f998577d547b1e54ec662dac63583aa11e3b84b/gpt_researcher/agent.py#L451-L492) · [空串保护](https://github.com/assafelovic/gpt-researcher/blob/6f998577d547b1e54ec662dac63583aa11e3b84b/gpt_researcher/skills/writer.py#L77-L124) · [LLM 调用与重试](https://github.com/assafelovic/gpt-researcher/blob/6f998577d547b1e54ec662dac63583aa11e3b84b/gpt_researcher/actions/report_generation.py#L249-L326)
9. **两路都空时，检查是否只剩段落标签。** `_get_context_by_web_search()` 没有有效子问题结果时返回 `[]`；本文范围内的 `join_local_web_documents()` 收到两个空列表后，仍会生成带两个段落标签的非空字符串。写作器用 `_ctx.strip()` 判断是否继续，这段只有标签的文本也能通过。由这些代码条件可以推得，应用还需检查是否至少有一份来源带着有效正文；本文尚未实际触发这组条件。单个子问题发生异常时，程序会记日志并返回空串；规划、装载等位于 `asyncio.gather()` 外部的异常，仍需沿调用方查看如何处理。[空子问题与异常](https://github.com/assafelovic/gpt-researcher/blob/6f998577d547b1e54ec662dac63583aa11e3b84b/gpt_researcher/skills/researcher.py#L380-L398) · [子问题错误返回](https://github.com/assafelovic/gpt-researcher/blob/6f998577d547b1e54ec662dac63583aa11e3b84b/gpt_researcher/skills/researcher.py#L644-L653) · [拼接与保护](https://github.com/assafelovic/gpt-researcher/blob/6f998577d547b1e54ec662dac63583aa11e3b84b/gpt_researcher/prompts.py#L563-L566) · [写作器判断](https://github.com/assafelovic/gpt-researcher/blob/6f998577d547b1e54ec662dac63583aa11e3b84b/gpt_researcher/skills/writer.py#L77-L88)

## 读完应能判断什么

回到技术调研的例子，可以沿“收集到的原文 → `researcher.context` → 报告”查看每次交接留下了什么。文档为空时，那一路也可以转去网页，所以报告依据要看实际来源、正文和引用。

本文依据固定 commit 的源码，空材料分支的结论是上面标出的静态推断。尚未运行检索器、加载本地文件、调用模型或验证真实报告引用。[来源台账](../../../sources/systems.json)已记录该提交的仓库根许可证，公开发布前还需检查子目录与第三方素材的使用许可。
