### 当前实跑通过点

- 七种模式各在新 Python 子进程实际运行，退出码为 `normal=0`、`timeout_then_lookup=0`、`same_id_retry=0`、`lookup_lag=2`、`late_commit=2`、`unsafe_new_id=2`、`payload_conflict=2`；对应宿主状态全部匹配正文，清理后登记数依次为 1、1、1、1、1、2、1，均报告关闭监听。没有访问远端网址或真实账号。
- `python3 -B -m unittest discover -s examples/http-receipt -p 'test_*.py' -v` 当前 **15/15 通过**，退出 0，约 1.23 秒。通过不证明上述强时序图已成立；两项是不同验收问题。本段没有开展测试独立性或生产协议审计。
- 真实部分、人工故障和业务模拟区分清楚：真正建立 loopback TCP/HTTP；事件闸门人为延后回复或登记；业务只有进程内标签账本，不是部署、不持久化，也不是互联网丢包。Python／loopback 前置条件、动态端口、非生产服务器和不绑定公网均已说明。
- 两种 404 解释准确：`lookup_lag` 隐藏已有记录；`late_commit` 的当前确实未登记，但旧请求稍后仍能登记。关闭连接／停止宿主判断没有被写成取消或回滚；`observer_after_cleanup` 的事后账本没有冒充宿主当时的证据。
- 同 ID／同内容的去重是当前服务合同而非 POST 自带属性；同 ID 换内容的 409 不覆盖原值。宿主确认检查 ID 与 payload，第二次超时不误报冲突。正文也没有把进程内锁说成分布式恰好一次。

上述延迟登记是额外的受控教学扰动，不是默认运行失败、网络性能测量或外部 API 结果；它只定位时序承诺的验证缺口。原先五项待主代理修订后另作落实核对，本段没有更改其状态。
