# 三篇图解试读：记录与判断方法

[试读页](../reader-trial.md) · [当前进度](../roadmap.md) · [教学任务 #4](https://github.com/chicogong/agent-systems/issues/4)

本页供维护者整理试读结果。2026-10-08 时只有试读题和判断标准，**尚无非作者真人反馈**。不把 Agent 冷读、网站访问数或答对术语计入人数。

## 怎样邀请与记录

先找 6–9 位未参与写作、背景不同的自愿读者，让每题至少有两位独立试读。每人任选一篇；不要求三篇连读，不要求运行代码。尽量覆盖网页、GitHub、PDF 与离线 Markdown 的实际阅读方式。不要为了凑人数收集身份、年龄、学校、单位或私人聊天记录。

记录所读篇、版本或日期、阅读方式、第一版独立回答、卡住的具体位置、提示种类、提示后回答和读者自提问题。没有回答也记为卡点。首次反馈能说明什么，就先据此修稿；至少找愿意复看的读者用修改后的版本再试一遍。公开整理只放脱敏摘要和修改位置。

## 三题要观察的理解

| 题目 | 独立回答应说明 | 常见误解与待改稿信号 |
| --- | --- | --- |
| A 保存与本轮可见 | `D1`、`D2` 已到本轮；`D3` 虽已保存，这轮没有返回。可以回答时间与地点，报名情况先留待查；需检索或读取 `D3`，并把原文送入下一次模型输入再核对。 | 说“资料库有，所以模型已经知道”，或把“找到文件”直接当成“回答已经用对”。 |
| B 发现与获准执行 | 工具发现、模型建议均已发生；这次调用到服务端权限检查后被拒绝。尚未取得 `D3` 原文，不能给出报名结论；向用户说明未读到的资料和可行的补充或授权方式。 | 把 Skill 指令或工具清单当作账户授权，或把被拒绝的读取写成成功。 |
| C 结束与任务完成 | 文件差异显示一项要求被破坏，单项测试通过不能覆盖重试规则；交付尚未满足用户要求。要对照 diff 检查重试项，补能同时检查两项要求的测试并复跑，报告现有结果和未完成项。 | 只凭“测试通过”或助手回复判完成；看见 diff 却没有拿原要求逐项核对。 |

判断只看解释与新情境中的动作，不要求使用“上下文”“Harness”等准确词。把答案分别记为：独立讲清、经一次提示讲清、仍有关键误解；同时记录是正文、图、例子、阅读器还是题意造成障碍。没有人数、版本和原始卡点，就不能写“读者已理解”。

## 何时修改文章

两位读者在同一节点或说法卡住，优先改那段正文或图的文字说明，并让另一位读者看修改版。若只有一位卡住，也记录具体误解并核对事实；不因为人数少就自动忽略。修订时保留固定源码范围、不同结果状态和执行条件。每次在 Issue #4 链接修改提交及复测结果，当前结果仍以[路线页](../roadmap.md)为准。
