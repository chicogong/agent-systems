# 2026-10-05 白话改稿与交叉检查

本轮按读者反馈调整写作方式：先讲一件具体事情，再解释谁做什么、结果交给谁。图解与日常应用是主线，源码和编程保留为可选深入入口。本文记录编辑与检查范围；发布版本由阅读站的 `/version.json` 另行标明。

## 改稿覆盖

同一书稿清单的 66 个单元中，65 个做了表达修改或新增；致谢保持原文。包括 14 篇机制、33 篇系统文章、6 篇对照、5 篇小实验，以及前言、阅读指南、学习路线、学习与应用导读、术语表、结语和作者简介。目录、README、网站首页和 Markdown 包索引同步，仍只维护一份源稿。

- 正常任务先讲完整。读书会材料贯穿运行循环、资料选择和回答检查；文件修改、查网页、运行测试等案例说明具体程序怎样接力。
- 首次使用英文术语时补中文解释。项目字段和函数名保留，便于源码搜索；初读概览尽量用“读取、选择、交给、检查、保存”说明动作。
- 减少反问、自问自答、连续否定，以及“切面、投影、合同、结算”等抽象表述。重要授权、费用和隐私提醒仍在实际操作之前。
- 完整版本、来源和未验证范围集中放在章末；详细审查留在维护记录。高级导读不作为图解阅读前置。
- [写作方法](../editorial-plan.md#用大白话讲清楚)、协作约定与[系统模板](../systems/TEMPLATE.md)已经补入这些规则，后续新稿按相同原则审读。

## 保留技术条件，修正含混表达

两组协作 Agent 分别核对八个系统的固定源码，每个系统重开至少两个核心主张的来源；随后交换目录审读全部 33 篇系统文章。概念、对照和五篇实验另做交叉阅读。详见[执行与源码检查](2026-10-05-execution-source-audit.md)、[状态与机制检查](2026-10-05-state-mechanism-audit.md)。这是 AI 编辑与源码复核，没有把它记成真人试读。

本轮修正了以下容易误解的地方：

1. OpenCode 工具调用有四类状态；mini-SWE-agent 的结果格式化不增加一次模型请求。
2. OpenHands 的宿主应先取得确认，再续跑等待中的动作；DSH 的结束意图由批次汇总后交上层处理。
3. Browser Use 的任务结束、动作完成、截图取得和截图是否进入模型输入分别说明。
4. MiMo 按开关和已有笔记选择重建或备用路径，首页改为简述，条件留在代码导读。Kimi 不再要求初读者先做函数自测。
5. Hermes 的审批拒绝与执行报错分开：前者不提交，后者可能已留下修改，需要读回检查。相关图与文字同步。
6. 取消请求与已停止分开；外部重试需有可靠的旧操作终态，或服务明确支持同键、同参数安全重放。
7. 部署例子补齐操作编号的来源与查询前提，回执丢失且暂无可靠查询时记录未知。
8. 状态对照表先用中文说明保存什么、怎样取用；Mem0 的托管平台和开源版成绩分开表述。
9. 普通读者复读后，将“材料正文还在外面”“共享内容则明确安排”“当前轮预授权”等改为具体动作；Agent loop 的说明改用图中实际的“模型决策”“观察结果”“验证”框名。
