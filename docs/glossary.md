# 术语表：把名字放回具体任务里

阅读 Agent 源码和架构文章时，最怕的不是生词多，而是**同一个词在两套框架里指代完全不同的东西**——比如同样叫 `checkpoint`，在一套系统里是可精确回滚的状态机数据库快照，在另一套系统里却只是一份喂给下一轮窗口的 Markdown 交接备忘录；同样叫“记忆”，有人指的是当前窗口里的几千个 Token，有人指的是跨月检索的向量库。

这份速查词典按四个工程切面整理全书核心术语：每个词先给**一句直达本质的大白话定义**，再点破**实战中最容易踩坑的混淆边界**。

## 一、控制流与执行角色

| 术语 | 一句话本质定义 | 最容易混淆的边界 | 继续阅读 |
| --- | --- | --- | --- |
| **Agent** | 围绕目标“先试一步 → 看真实反馈 → 再决定下一步怎么走”的闭环运行系统 | **不等于大模型本身**：裸模型只会输入文本吐出文本，加上宿主循环、工具与状态管理才构成 Agent | [三种任务组织方式](concepts/agent-workflow-multiagent.md) |
| **工作流**（Workflow） | 由工程师提前画好固定步骤、分支条件与先后顺序的执行管线 | **不等于自主循环**：工作流由代码定死路线，Agent 则在循环里把“下一步调谁”交给模型动态判断 | [工作流与 Agent](concepts/agent-workflow-multiagent.md) |
| **多 Agent／多执行者** | 把复杂任务拆给多个拥有独立上下文或专长权限的执行者，再汇总核验结果 | **不是人多就一定更强**：每多一层交接就多一次信息损耗与协调开销，单 Agent 能清晰闭环时不必硬拆 | [委派与交接](concepts/delegation-and-handoff.md) |
| **Agent loop**（运行循环） | “模型提动作提案 → 宿主审验并执行工具 → 把结果喂回模型继续判断”直到停机的核心循环 | **循环停下不等于任务成功**：撞上步数上限、用户取消或连续报错同样会让循环退出 | [运行循环](concepts/agent-loop.md) |
| **Harness／运行器／宿主** | 包在模型外层、负责组装上下文、拦截权限、调度工具与管理状态的工程骨架 | **真正的拍板者是宿主而非模型**：模型只能“打报告提建议”，能不能执行、写到哪全由宿主代码说了算 | [一项任务的分工](concepts/model-harness-cli-mcp-skill.md) |
| **CLI**（命令行界面） | 用户在终端里提交指令、查看流式进展与点按审批的交互入口 | **只是外壳而非内核**：同一个底层 Harness 既可以挂终端 CLI，也可以挂桌面端或后台非交互服务 | [职责分工](concepts/model-harness-cli-mcp-skill.md) |
| **Tool／工具** | 宿主暴露给模型调用的确定性函数接口（如读文件、跑命令、查工单） | **工具成功只代表 I/O 跑通**：例如写文件工具返回 `ok=true`，不代表写进去的配置符合业务不变量 | [工具怎样接入](concepts/extensibility-layers.md) |
| **Proposal／提案** | 模型输出的“我建议下一步调用某工具及对应参数”的结构化意图 | **提案尚未产生任何外部变化**：在穿过宿主审批与执行器之前，它只是一段待审的 JSON 文本 | [运行循环](concepts/agent-loop.md) |
| **Observation／观察** | 工具执行（或执行前被拒）后带回循环的真实输出、报错信息或状态回执 | **观察属于不可信外部输入**：文件内容或网页返回里可能混有诱导越权的指令，不能自动升级宿主权限 | [OpenHands](systems/openhands/README.md) |

## 二、上下文、状态与记忆

| 术语 | 一句话本质定义 | 最容易混淆的边界 | 继续阅读 |
| --- | --- | --- | --- |
| **当前上下文**（Context） | **这一次**调用大模型接口时，请求载荷里真正传过去的指令、历史与材料字节 | **存进磁盘不等于进入当前上下文**：没被分支选中、没被检索捞中或超出窗口被裁掉的内容，模型一个字也看不见 | [上下文与记忆](concepts/context-vs-memory.md) |
| **Token** | 模型把文本切碎后用于计费和计算窗口容量的基本片段单位 | **不等于字符数或字节数**：中英文、代码符号与工具 Schema 的 Token 折算比例各不相同 | [上下文预算](labs/context-budget.md) |
| **输入预算** | 本次请求在扣除系统提示、工具定义与预留输出空间后，还能塞进多少历史与参考材料 | **扩大窗口不等于消除取舍**：塞进太多无关日志会稀释模型对早期核心约束的注意力 | [上下文与记忆](concepts/context-vs-memory.md) |
| **会话记录** | 应用在本地或数据库里持久保存的完整聊天消息、分支节点与工具事件流 | **通常是单场会话隔离的**：重开新会话不会自动带上旧会话记录，长会话内回退分支也会隐去旁支记录 | [四类状态](comparisons/four-kinds-of-state.md) |
| **压缩摘要**（Compaction） | 当对话快撑爆窗口时，把早期冗长交互浓缩成短摘要，腾出空间继续接近期消息 | **有损操作**：早期的细碎数字或顺口提过的禁令（如“切勿推送”）可能在概括时丢失，硬红线须另靠宿主规则守住 | [会话变长以后](concepts/session-compaction-and-memory.md) |
| **长期记忆** | 跨会话保留下来、供日后直接编入提示词或按需检索召回的用户偏好、规范与历史事实 | **实现形态截然不同**：Letta 偏重常驻与分层的可编辑 Markdown 文件，Mem0 偏重抽取后的向量检索候选 | [Letta Code](systems/letta/README.md)、[Mem0](systems/mem0/README.md) |
| **Checkpoint／检查点** | 图或工作流引擎在步骤边界保存的结构化程序执行状态快照，支持断点续跑与分叉 | **只回滚内存变量，不回滚外部世界**：切回旧检查点重跑，绝不会自动撤回之前已经发出去的邮件或部署请求 | [LangGraph](systems/langgraph/README.md) |
| `checkpoint.md` | MiMo Code 中把阶段性任务目标、已完成进展与关键线索整理给后续模型窗口读的交接文档 | **撞名预警**：它是一份面向模型阅读的上下文压缩与交接文本，**不是** LangGraph 那种引擎级状态机快照 | [MiMo Code](systems/mimo-code/README.md) |

## 三、权限、隔离与外部副作用

| 术语 | 一句话本质定义 | 最容易混淆的边界 | 继续阅读 |
| --- | --- | --- | --- |
| **审批**（Approval） | 在动作真正执行前，由人类或宿主策略拍板“这一次调用准不准放行” | **管准入不管爆炸半径**：就算你点同意跑 `npm test`，测试脚本里如果藏着删库或外发请求，单靠审批本身拦不住 | [审批与沙箱](concepts/approval-vs-sandbox.md) |
| **沙箱／隔离**（Sandbox） | 用操作系统或容器机制限制运行中进程能读写哪些目录、访问哪些网络地址 | **本地沙箱管不住远端工具**：给本地 Bash 套了严密沙箱，挂在旁边的 MCP 工具照样能凭 Token 直接改远端线上工单 | [沙箱执行环境](concepts/sandbox-execution.md) |
| **副作用**（Side Effect） | 工具对本地工作区或外部真实世界造成的实质状态改变（改文件、写库、发信、发布） | **超时不代表副作用没发生**：跨网络写操作报 `Timeout` 时，远端很可能早已执行成功，只是回执断在了回程 | [中断与恢复](concepts/interruption-recovery.md) |
| **操作 ID／幂等键** | 发送请求前由客户端分配的唯一业务单号，供超时对账查询与服务端重复请求去重 | **客户端光传 ID 没用**：必须目标服务端在锁内真正实现了“同键同参返回原结果、不重复执行”，重放才安全 | [回执丢失](labs/remote-effect.md) |

## 四、能力扩展与本书研究口径

| 术语 | 一句话本质定义 | 最容易混淆的边界 | 继续阅读 |
| --- | --- | --- | --- |
| **Skill** | 按需加载进上下文的专项任务做法说明、操作规范及配套脚本资源 | **省预算的软指导**：不用时不必挤占每轮常驻提示词；但它本身只是说明文档，不会越过宿主偷偷拿到额外系统权限 | [扩展能力](concepts/extensibility-layers.md) |
| **Extension／扩展** | 直接由宿主进程加载运行的插件代码，能注册新工具或挂载生命周期钩子 | **代码级高权限**：不同于纯文本 Skill，扩展在宿主运行期内直接参与控制流与事件拦截 | [Pi 扩展](systems/pi/extensions-and-skills.md) |
| **MCP** | 让宿主以统一协议连接外部服务并获取工具、资源与提示模板的标准接口 | **通道标准不等于权限免检**：连上了 MCP Server 后，具体哪个工具免询、哪个必须弹窗、用谁的身份访问仍须独立管控 | [工具怎样接力](concepts/mcp-skill-tool-lifecycle.md) |
| **源码事实** | 在本书登记的固定仓库提交与具体文件行号中，能够逐行核对到实现代码的结论 | **仅对该提交与所读路径负责**：上游仓库后续升级或其他未展开分支（如特定平台插件）可能存在差异 | [来源规则](../sources/README.md) |
| **工程推断** | 基于多套源码机制与分布式系统常识提炼出的架构权衡建议或排查方法 | **不是某一个项目的专有 API**：正文中会明确区分“源码里写了什么”与“你在设计系统时该补哪道防线” | [来源规则](../sources/README.md) |

## 读完怎样用这张表？

下次阅读任何一个新冒出来的 Agent 框架或产品文档时，不妨挑三个最容易被宣传词糊弄的问题直接拷问它：

1. 它嘴里说的“记忆”，到底存在哪一层，什么时候真正拼进本次请求的 `messages`？
2. 它嘴里说的“安全受控”，到底是提示词劝导、执行前弹窗审批，还是进程级 OS 沙箱？
3. 当一个写操作中途断连后，它所谓的 `checkpoint` 恢复，会不会把外部接口再重打一遍？

抓准这三问，绝大多数花哨的新名词都会瞬间落回你熟悉的工程底座上。
