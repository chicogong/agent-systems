# Hermes 代码导读：追踪经验的读取、暂存、后台复盘与快照刷新

# Hermes 代码导读：追踪经验的读取、暂存、后台复盘与快照刷新

[返回 Hermes 剖面](README.md) · [上下文预算练习](../../labs/context-budget.md)

当编码助手一边守着“严禁触碰生产库”的环境红线排查测试故障，一边把新摸索出的排障套路沉淀成下次可用的 Skill 时，底层代码究竟在哪一刻锁住了系统提示快照、在哪一刻把高危改动拦进 `staged` 队列、又在哪一刻拉起后台复盘？下面沿着 [`NousResearch/hermes-agent@a9109b07f42685f88397008d0d5a6c3d481b3b28`](https://github.com/NousResearch/hermes-agent/tree/a9109b07f42685f88397008d0d5a6c3d481b3b28) 的真实调用链走完这八个关键节点。

## 八步走完跨会话知识的完整生命周期

### 1. 会话入口：先让路给前台请求，再挂接回合收尾

用户发来新消息时，调用首先进入 [`TurnFacadeMixin.run_conversation()`](https://github.com/NousResearch/hermes-agent/blob/a9109b07f42685f88397008d0d5a6c3d481b3b28/agent/turn_facade.py#L22-L44)。注意它的第一个动作不是直接调模型，而是先检查并取消上一轮可能仍在后台运行的知识复查任务，避免后台整理与前台新对话争抢状态，随后在[同文件 142–154 行](https://github.com/NousResearch/hermes-agent/blob/a9109b07f42685f88397008d0d5a6c3d481b3b28/agent/turn_facade.py#L142-L154)把控制权转交给会话主循环。

主循环 [`agent/conversation_loop.py`](https://github.com/NousResearch/hermes-agent/blob/a9109b07f42685f88397008d0d5a6c3d481b3b28/agent/conversation_loop.py#L1643-L1689) 负责驱动多步工具调用与模型响应，并在整轮对话结束时调用收尾器（finalizer）——那里正是盘后后台复盘的触发点。阅读 `run_agent.py` 中的 `AIAgent` 时，顺着这层 Mixin 转发就能定位各职责模块。

### 2. 初始化短记忆：把实时状态与提示快照一分为二

Agent 启动阶段，[`_init_memory()`](https://github.com/NousResearch/hermes-agent/blob/a9109b07f42685f88397008d0d5a6c3d481b3b28/agent/agent_init.py#L1286-L1323) 根据 `skip_memory` 配置与内置 memory 工具的启用情况创建 `MemoryStore` 实例，并调用 `load_from_disk()` 从磁盘装载 `MEMORY.md` 与 `USER.md`。

打开 [`MemoryStore`](https://github.com/NousResearch/hermes-agent/blob/a9109b07f42685f88397008d0d5a6c3d481b3b28/tools/memory_tool_store.py#L88-L164) 可以看到它最核心的数据结构设计：内部同时维护动态变化的当前条目（live entries）与冻结的 `_system_prompt_snapshot`。加载器在读盘时做去重并生成快照；若发现外部编辑器手工塞入了超配额内容，不会粗暴截断磁盘文件，而是在加载时记录提醒；针对特定可疑注入内容的扫描与替换也只作用于送往模型的提示快照，保留磁盘原始文本不变。

### 3. 拼装系统提示：全文常驻与轻量索引的分流

准备系统提示时，短记忆与长流程在这里分道扬镳：

- **短记忆走快照直装**：[`_memory_parts()`](https://github.com/NousResearch/hermes-agent/blob/a9109b07f42685f88397008d0d5a6c3d481b3b28/agent/system_prompt.py#L515-L539) 调用 `format_for_system_prompt()`，直接把 `_system_prompt_snapshot` 嵌进系统提示（若配置了外部记忆 provider，也会在此处追加其提示块）。
- **长流程走目录索引**：[`_render_skills_index()`](https://github.com/NousResearch/hermes-agent/blob/a9109b07f42685f88397008d0d5a6c3d481b3b28/agent/prompt_builder.py#L1359-L1415) 遍历可用 Skills，只把名称与简短描述压成紧凑目录（部分类别甚至只列名称），把几百行的 `SKILL.md` 正文挡在初始上下文门外。

### 4. 按需展开 Skill：从一行目录变成当轮工具结果

当模型在目录里看到匹配当前测试故障的 Skill 时，发起 [`skill_view()`](https://github.com/NousResearch/hermes-agent/blob/a9109b07f42685f88397008d0d5a6c3d481b3b28/tools/skills_tool.py#L573-L693) 调用。该函数依次完成名称解析、平台兼容性与禁用状态检查：

- 不带具体子文件路径时，返回 `SKILL.md` 正文、元数据以及同目录下的关联文件列表；
- 需要查阅附带脚本或参考表时，模型再传 `file_path` 二次按需读取；
- 默认路径在返回正文前还会执行 `preprocess` 预处理，并尝试激活该 Skill 声明的工具依赖。

### 5. 修改短记忆：门禁校验、整条替换与原子写盘

排障途中若要写入新的环境约束，调用进入 [`memory_tool()`](https://github.com/NousResearch/hermes-agent/blob/a9109b07f42685f88397008d0d5a6c3d481b3b28/tools/memory_tool.py#L208-L250)（支持单条操作或批量列表）。通过参数校验、无人值守删除门禁与写入审批检查后，才真正进入存储层变更：

1. [`_mutate()`](https://github.com/NousResearch/hermes-agent/blob/a9109b07f42685f88397008d0d5a6c3d481b3b28/tools/memory_tool_store.py#L245-L295) 先加锁、重新从磁盘读取最新状态，执行完变更函数后再落盘，防止并发调用互相覆盖。
2. [`replace()` / `_edit()`](https://github.com/NousResearch/hermes-agent/blob/a9109b07f42685f88397008d0d5a6c3d481b3b28/tools/memory_tool_store.py#L298-L362) 用 `old_text` 定位唯一匹配的整条记录，并将**整条 entry** 替换为新文本；若超出字符容量或命中多条歧义记录则直接拒绝。
3. 落盘环节采用[临时文件加原子替换](https://github.com/NousResearch/hermes-agent/blob/a9109b07f42685f88397008d0d5a6c3d481b3b28/tools/memory_tool_store.py#L520-L528)，确保磁盘上不会出现写到一半截断的 `MEMORY.md`。
4. [成功回包](https://github.com/NousResearch/hermes-agent/blob/a9109b07f42685f88397008d0d5a6c3d481b3b28/tools/memory_tool_store.py#L463-L481)返回当前字符用量与条目计数摘要（注意该版本的成功响应并不会统一把全部 `live entries` 原文回显一遍，核对完整内容仍需直接查存储）。

### 6. 维护 Skill：认清 `staged` 暂存态与落盘态的分野

当模型调用 [`skill_manage()`](https://github.com/NousResearch/hermes-agent/blob/a9109b07f42685f88397008d0d5a6c3d481b3b28/tools/skill_manager_tool.py#L767-L818) 新建或修订排查流程时，代码依次经过批量拆分、后台权限约束、审批门禁与文件锁，再分发给具体操作 handler。

这里最值得留意的是审批分支：[通用审批决策](https://github.com/NousResearch/hermes-agent/blob/a9109b07f42685f88397008d0d5a6c3d481b3b28/tools/write_approval.py#L169-L193)把结果分成直接放行、暂存待批与显式拒绝三档；一旦命中暂存，[Skill 门禁](https://github.com/NousResearch/hermes-agent/blob/a9109b07f42685f88397008d0d5a6c3d481b3b28/tools/skill_manager_tool.py#L618-L648)会返回带 `staged` 标记的结果，把改动挂进待批准队列等待人工重放落盘（另外留意一处实现细节：若审批模块本身导入失败，当前 Skill 门禁走的是 fail-open 放行分支，做安全加固时需一并关注运行环境依赖完整性）。

### 7. 盘后后台 `review fork`：戴着镣铐提炼知识

主对话一轮结束时，[`finalize_turn()` 的触发段](https://github.com/NousResearch/hermes-agent/blob/a9109b07f42685f88397008d0d5a6c3d481b3b28/agent/turn_finalizer.py#L734-L763)逐项核对轮次计数、知识工具可用性、是否已产出最终答复、是否被中断以及后台复查开关。全部放行后，宿主才会拉起独立的后台 review fork。

为了让这个无人值守的后台分支“只整理笔记、不乱动系统”，代码给它套上了两重紧箍咒：

```text
后台 review fork 启动
  ├── 工具范围限制：按默认白名单派发，剔除 terminal 与普通文件写入工具（除非配置 extra_tools）
  ├── 输入范围裁剪：读取当前会话快照或经路由缩减后的历史上下文
  └── 删除/替换拦截：无人值守状态下调用 memory replace/remove 强制转入暂存待批，暂存失败直接拒绝
```

这三处约束分别对应[派发白名单](https://github.com/NousResearch/hermes-agent/blob/a9109b07f42685f88397008d0d5a6c3d481b3b28/agent/background_review.py#L1083-L1124)、[执行段](https://github.com/NousResearch/hermes-agent/blob/a9109b07f42685f88397008d0d5a6c3d481b3b28/agent/background_review.py#L1142-L1188)与[暂存门禁](https://github.com/NousResearch/hermes-agent/blob/a9109b07f42685f88397008d0d5a6c3d481b3b28/tools/memory_tool.py#L167-L204)。

### 8. 追到提示重建边界：新记忆何时真正浮出水面

即便新记忆已经通过审批写进了 `MEMORY.md`，[`format_for_system_prompt()`](https://github.com/NousResearch/hermes-agent/blob/a9109b07f42685f88397008d0d5a6c3d481b3b28/tools/memory_tool_store.py#L463-L466) 在当前会话里依然返回启动时锁定的 `_system_prompt_snapshot`。

真正触发换血的位置在[压缩提交边界](https://github.com/NousResearch/hermes-agent/blob/a9109b07f42685f88397008d0d5a6c3d481b3b28/agent/conversation_compression.py#L3144-L3188)：当长会话完成一次上下文压缩提交时，代码显式调用 `invalidate` 淘汰旧的系统提示缓存，随后由[提示失效逻辑](https://github.com/NousResearch/hermes-agent/blob/a9109b07f42685f88397008d0d5a6c3d481b3b28/agent/system_prompt.py#L790-L820)重新读取存储并组装新版系统提示（唯有携带预置 `seeded prompt` 的 `detached` 分离回合会提前返回，继续沿用预置提示）。
