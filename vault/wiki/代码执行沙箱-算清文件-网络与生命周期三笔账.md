- 赋予 Agent“写脚本并直接运行”的能力，本质上是把“任意代码执行”做成了在线功能。很多团队随手拉起一个默认配置的容器，顺手挂上目录 `-v $HOME:/workspace` 就以为进了保险箱——直到 Agent 解析一份外部报表时触发恶意依赖或间接提示注入，脚本不仅顺着挂载目录读光了本地云凭据，还借道默认放行的容器外网把数据传了出去，甚至在任务超时后留
- 真正兜得住风险的**沙箱**（Sandbox），绝不只是套一层容器外壳，而必须在创建之初就算清三笔硬账：**文件系统边界、网络与凭据出入口控制、进程生命周期与状态清理**；同时还要看清容器、gVisor 与 microVM 各自挡在操作系统内核的哪一层，以及为什么**销毁本地沙箱永远撤不回已经发往远端的外部 API 请求**。
