- 你花半小时陪 Agent 排完一次棘手的集成测试失败：先确认测试只能跑在隔离容器里、绝不能连生产库，再顺着连接池快照定位到超时根因。关掉当前窗口后，下次再开新会话遇到同类报错，普通助手往往忘得一干二净；可如果反过来放任 Agent 自动把每次对话总结塞进系统提示，不出几天提示词就会膨胀成流水账，甚至把某次偶然猜错的结论当成“项目铁律”永久写死，静默污染后续所
- Hermes Agent 在宿主层搭了一套严密的**跨会话经验治理管线**（不涉及模型权重微调，全部作用于宿主文件与上下文组装）：把高频短约束关进字符受限的 `MEMORY.md / USER.md`，把长篇操作手册拆成按需 `skill_view` 的 Skill，在任务收尾后拉起权限受限的后台 **review fork** 提炼经验，并用**系统提示快
- 同样是“下次还要用的经验”，一句环境红线和一套七步排障SOP对上下文的消耗完全不同。Hermes 在存储入口就把它们拆成了两条轨道：
- - **高频短事实写入字符受限的记忆文件**：`MEMORY.md` 存放项目与环境事实（默认上限 **2,200 个字符**），`USER.md` 存放用户偏好与背景（默认上限 **1,375 个字符**）。注意这里按字符数而非 token 硬卡上限，随系统提示常驻加载；如果是外部手工塞入了超长文件，加载器会保留磁盘原文但主动发出超限提醒。内置存储与加载
- - **多步操作手册写成可复用的 Skill**：排障流程、部署清单这类长文本写成独立的 `SKILL.md`。系统提示在启动时只渲染一份轻量的「**名称 + 简述**」目录索引；只有当模型判断当前任务需要这套方法时，才主动调用 `skill_view` 把正文及关联参考文件读入当轮工具结果。索引生成 · 按需读取
